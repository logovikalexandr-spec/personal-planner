# Команда агентов planner-v2 — взаимоотношения

> Зафиксировано 2026-05-30. Кто кому передаёт, кто кого тормозит, как идёт обратная связь. Цель — глубина без пинка пользователя, один контакт с пользователем.

## Иерархия
- **CEO-координатор (главный AI)** — единственный, кто говорит с пользователем. Раскладывает работу по фазам, сводит результаты, гейтит, показывает мокапы, относит продуктовые развилки пользователю. Сам код не пишет.
- Все агенты подчинены CEO и общаются между собой только через артефакты (спека / контракт / отчёт), не «на словах».
- **С пользователем говорит только CEO.** Агенты пользователю не пишут.

## Поток по фазам (кто → кому)

```
ФАЗА 1 — РАЗВЕДКА (мокапы, без кода)
  product-depth ──deep-спека + reuse-карта──▶ designer ──визуал-мокапы──▶ CEO ──▶ ПОЛЬЗОВАТЕЛЬ (смотрит, рулит, утверждает)
       ▲ консультация выполнимости │ architect
       ▲ «это состояние нечем показать» │ designer

ФАЗА 2 — СБОРКА до глубины
  architect ──контракты API+схема──▶ backend ∥ frontend ──код по всей матрице состояний──▶
  designer ──визуал-токены по DESIGN.md──▶ frontend

ФАЗА 3 — ГЕЙТ (конвейер верности v2, автоматический)
  lint:tokens (нет сырого hex/битых var) ──▶ vitest (unit) ──▶
  e2e Playwright: визуал-baseline + токен-смоук + поведение/состояния ──▶
  coverage.sh (каждый ecode мокапа покрыт или явно отложен) ──▶
  reviewer ──depth-гейт: MERGE / BLOCK (НЕ MERGE пока e2e не зелёный)──▶
  CEO ──deploy-гейт: тот же e2e против прод-URL──▶ ПОЛЬЗОВАТЕЛЬ (финальное ОК)
```

## КОНВЕЙЕР ВЕРНОСТИ v2 (2026-06-14, заменил ручной гейт 2026-06-09) — «дал задание = получил то, что хотел»

> Дизайн: `контекст/спеки/2026-06-14-конвейер-v2-playwright-design.md`. Профи-стек после аудита: **предотвращение в источнике + детерминированная сверка против эталона, утверждённого человеком 1 раз.**
> Корень дыры «мокап≠деплой»: гейт был полу-ручной + **Claude судил свой код** (ревью текста, не рендера). Заменено машинной сверкой.

**Слой ПРЕДОТВРАЩЕНИЯ (дрейф невозможен в коде):**
- `theme.css` = токены (CSS vars). Код берёт цвет/шрифт/отступ ИЗ токена, не хардкодом.
- `npm run lint:tokens` (`tools/check-tokens.sh`) — статически ловит сырой hex + битые `var()`. PASS обязателен. (Нашёл 5 тихих багов цвета при заведении.)

**Гейт ФАЗЫ 3 (детерминированный, Playwright):**
1. `npm run lint:tokens` — токены чисты.
2. `npm run test` (vitest) — unit зелёные.
3. `npm run e2e` (`tests-e2e/<screen>.spec.ts`) — контракт экрана = ИСПОЛНЯЕМЫЕ тесты (не инертный YAML):
   - **визуал-baseline** (`toHavescreenshot` vs эталон, утв. человеком) — против дрейфа вида;
   - **токен-смоук** (`toHaveCSS`) — var() резолвится в нужный цвет DESIGN.md;
   - **поведение + состояния** (empty/loading/error, флоу, persist после reload).
4. `bash tests-e2e/coverage.sh <mockup> <spec>` — каждый `ecode` мокапа ПОКРЫТ тестом или ЯВНО отложен (COVERAGE-DEFER). Молчаливых дыр нет.
5. Деплой-гейт: тот же `e2e` против прод-URL (`PLAYWRIGHT_BASE_URL=…`).

**Честность (Claude судит свой код — слепая зона):** эталон визуала утверждает ЧЕЛОВЕК один раз; **агент/CI НЕ запускает `--update-snapshots`** (config: `updateSnapshots:"none"`). Резерв — модель другого семейства как судья.

**Block-полномочие:** reviewer НЕ MERGE, CEO НЕ deploy пока `lint:tokens` + `e2e` + `coverage.sh` не зелёные.
**Golden example:** `tests-e2e/T1-today.spec.ts` (экран «Сегодня», 7 тестов ×2 браузера). Шаблон для остальных экранов.

## Кто кого тормозит (block-полномочия)
- **product-depth** — не пускает фичу в Фазу 2, если есть только happy-path без матрицы состояний и reuse-карты.
- **reviewer** — BLOCK merge при неполной глубине или несогласованности поведения.
- **qa** — стоп при красных тестах или непроверенном критичном пути.
- **CEO** — гейт деплоя. **Пользователь** — финальное визуальное ОК.

## Обратные связи (петли)
- reviewer BLOCK / qa fail → backend|frontend чинят → повтор гейта.
- frontend/backend упёрся в неясность: тех-развилка → architect; продуктовая развилка → product-depth → CEO → пользователь.
- designer не может показать состояние → пинг product-depth дополнить deep-спеку.

## Правила взаимодействия
1. Один источник правды на фазу: Фаза 1 = deep-спека product-depth; Фаза 2 = контракты architect; гейт = матрица состояний + reuse-карта.
2. Передача = структурированный артефакт, не разговор.
3. Общие файлы (theme.css, App.tsx, icons.tsx) — строго последовательно (параллель = гонка на дереве). Независимое — параллельно.
4. Кастомные роли в Workflow задаются ПРОМПТОМ (agentType-реестр кастомные `.claude/agents` не видит).
5. Глубина — общий KPI. Пользователь не должен находить дыры; их находит product-depth + reviewer.
