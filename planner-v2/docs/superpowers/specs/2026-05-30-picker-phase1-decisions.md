# Picker категории/проекта — Фаза 1 РАЗВЕДКА: решения

**Дата:** 2026-05-30. Пилот процесса «Глубина сначала». Фича: `ProjectPickerSheet` (`frontend/src/components/pickers.tsx`), открывается из `TaskComposer`.

## Корень проблемы (product-depth, из кода)
«Баг» НЕ в onClose — picker закрывается на каждом тапе. Реальная дыра — **рассинхрон паттернов**:
- picker = плоское ВСЕГДА-развёрнутое дерево, тап = выбор + закрыть;
- дерево в Drawer/Lists (`ProjectTree`) = сворачиваемое (expanded:Set + chevron), тап = навигация без закрытия.
Пользователь по привычке из дерева ждёт «тап родителя = раскрыть», picker вместо этого выбирает.

## Решённые развилки (CEO)
1. **Тап по родителю с детьми → A: выбрать+закрыть.** Дерево остаётся всегда-развёрнутым, родитель = валидный проект задачи. Один тап до выбора, нет ложного ожидания «раскрыть». Убирает корень рассинхрона.
2. **Галочка выбора → B: микро-пауза ~140мс.** Подсветить выбранную строку + ✓, затем закрыть (DESIGN §6, transform/opacity). Тактильный отклик «выбрал именно это».
3. **Создание проекта из picker'а → A: строка «+ Новый проект»** (открывает ProjectSheet), как тег в TagPicker. Убирает тупик пустого состояния. Нужен рефетч/локальный апдейт списка после создания.
4. **Глубина >2 → A: clamp отступа** `min(depth,3)*N` — имя читаемо на узком экране.

## Матрица состояний к реализации (Фаза 2)
пусто → строка-CTA «+ Новый проект» (+опц. muted-подсказка); загрузка → скелетон строк (не спиннер, DESIGN §7); выбрано → подсветка+✓ с паузой 140мс; субкатегория → отступ+связь с родителем; край (глубина) → clamp отступа, ellipsis имени; ошибка → отличима от «нет проектов», ретрай (не тишина).

## Reuse / дедуп (к реализации)
- **Вынести построение дерева** `flatten(projects, expanded?)` в общий `lib/projectTree.ts` — сейчас byParent-логика скопирована в pickers.tsx, ProjectTree.tsx, Drawer.tsx (3+ копии).
- Конвенция single-select picker «тап → onPick()+onClose()» — общий хелпер, не дублировать руками.
- Строку «+ Новый проект» — общий паттерн с Drawer/Lists `drawer-add`.
