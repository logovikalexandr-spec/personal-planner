## 1. Контекст и проблема

planner-v2 — личная life-OS (Telegram Mini App + бот + позже AI-копайлот), single-user, TickTick-клон на стеке FastAPI + Postgres + React/TS + aiogram + Caddy + Docker. Прод живой (VPS 188.245.42.4).

**Что построено к старту этой сессии:** категории+проекты (drag, ProjectSheet), календарь только Day-view, полный TaskComposer, модель Task с временем/повтором/напоминанием/тегами. Тесты 63 зелёных.

**Проблема, вскрытая в брейнсторме:** нижняя навигация размыта. 5 табов (Сегодня / Календарь / Задачи / Цели / Проекты) дублируют друг друга и не складываются в осмысленный поток:
- «Сегодня» — плоский список, не таймлайн.
- «Задачи» = «Все задачи», «Проекты» = просто открывает Drawer → две двери в одну навигацию.
- «Цели» — пустой плейсхолдер.
- «Календарь» — только один Day-view.

Тудушники на рынке страдают тем же: режимы *планировать / делать / анализировать* живут раздельно, закрытая задача исчезает без обратной связи о жизни.

## 2. Видение (инновация)

Один замкнутый контур **планируй → делай → смотри назад**, где закрытие задачи кормит трекинг, а трекинг кормит планирование. Не «список дел» — **зеркало жизни** с AI-копайлотом, знающим весь контекст. Это ключевое отличие от TickTick: обратная связь о прожитом, а не только чек-бокс.

**Не цель:** многопользовательность, мобильное нативное приложение (только Mini App), публичный релиз.

## 3. Информационная архитектура — 5 табов

| Таб | Работа | Содержимое |
|-----|--------|------------|
| **Сегодня** | делать | Гибрид: таймлайн по часам сверху + список «без времени» снизу + Inbox-карточка + мини-сводка дня (сколько задач/закрыто). Текущий Day-view (Calendar.tsx) — основа. |
| **Календарь** | планировать вперёд | Месяц-сетка с плотностью: интенсивность фона = приоритетная нагрузка дня, бейдж = число задач. Клик день → панель карточек задач (сорт время/приоритет). Переключатель Неделя/Месяц. |
| **Списки** | организовать | Один экран: смарт-вью (Inbox / Все / Сегодня / Запланированные / Теги) + дерево проектов (drag, вложенность, pin). Тап список → его задачи. Заменяет старые табы Задачи + Проекты + Drawer. |
| **Цели** | стремиться | Цели с дедлайном и прогресс-баром, связь с задачами/проектами. Строится с нуля (сейчас плейсхолдер). |
| **Трекинг** | смотреть назад | Теплокарта года (выполненные задачи) + дашборд метрик (кольца %, тренд недели, баланс сфер) + лента сделанного (ретро) + привычки (habit-tracker). |

Плавающие поверх любого таба: **＋ FAB** (создать задачу через TaskComposer) и **🤖 AI-копайлот** (разговорный слой, последняя волна).

### 3.1 Детали по табам

**Сегодня (гибрид).** Сверху — часовой таймлайн (переиспользуем существующий Calendar.tsx Day-view: блоки по due_time/end_time, цвет категории, линия «сейчас», тап по часу = TaskComposer с преднабранным временем). Снизу — секция «Без времени»: задачи на сегодня без due_time как список-чипы/карточки. Сверху — Inbox-карточка «Разобрать» (как в текущем Today.tsx). Мини-сводка дня: «N задач · M закрыто · ~Xч запланировано». Навигация по дням: остаётся на сегодня (свайп ±день — опционально).

**Календарь (плотность).** Месяц-грид 7×N. Каждая ячейка: число дня, бейдж количества открытых задач, цвет/интенсивность фона по максимальному приоритету дня (none→high). Клик день → нижняя/боковая панель с карточками задач этого дня, сорт по времени или приоритету (переключатель). Заголовок месяца + ‹ Сегодня ›. Тогл Неделя/Месяц (неделя = 7 колонок с задачами).

**Списки.** Верх — смарт-вью строками с счётчиками (Inbox, Все, Сегодня, Запланированные, по тегам). Низ — дерево проектов (текущий ProjectTree: drag-reorder в пределах родителя, long-press меню, ProjectSheet create/edit). Тап любой строки → ListView отфильтрованный. Старый Drawer удаляется (или превращается в этот таб; quick-switch свайпом — опционально).

**Цели.** Новая сущность. Список целей: название, дедлайн, прогресс (0–100% или счётчик), связанные задачи/проект. Создание/редактирование через sheet. Прогресс может считаться от связанных задач (доля done) или вестись вручную.

**Трекинг.** Скролл-экран из секций:
- *Теплокарта года* — год-в-пикселях, клетка/день, цвет по числу выполненных задач (done_at).
- *Дашборд* — кольца (% выполнено сегодня/неделя), тренд за 7/30 дней, баланс по сферам (группировка по корневым проектам/категориям).
- *Лента сделанного* — реверс-хронология закрытых задач, группировка по дням; основа для еженедельного ретро.
- *Привычки* — сетка привычек по дням, отметка, стрик.

## 4. Модель данных — дельты к существующей

Существующее (не трогаем структурно): `Project`, `Task` (есть done_at, due_date/time, end_time, recurrence, reminder_at, priority none/low/medium/high, status todo/in_progress/done/archived, parent_task_id, order_index), `Tag`, `TaskTag`, `InboxItem`, `Attachment`.

Новое:

- **Goal** (новая таблица): `id, title, description, target_date(date|null), progress_kind('manual'|'tasks'), progress_value(int 0..100), project_id(fk|null), status('active'|'done'|'archived'), created_at, done_at`.
- **GoalTask** (м2м, опционально): связь цель↔задачи для авто-прогресса. Альтернатива: фильтр по project_id. Решить на этапе планирования.
- **Habit** (новая): `id, title, icon, color, schedule(json: дни недели/частота), target_per_period(int), created_at, archived`.
- **HabitLog** (новая): `id, habit_id(fk), log_date(date), value(int default 1), created_at`. Уникальность (habit_id, log_date).
- **TaskTimeLog** (новая, опционально — для фокус/факт в Сегодня): `id, task_id(fk), started_at, ended_at(null=идёт), created_at`.

Агрегаты трекинга (теплокарта, дашборд, лента) считаются на лету из `task.done_at` — новых таблиц не требуют для MVP.

Смарт-ключи: добавить `planned` (есть due_date в будущем) к существующим (all/today/tomorrow/next7/week/inbox). Теги-вью — фильтр по tag_id.

Все изменения схемы — через Alembic-миграции (последняя на старте: c3d2e1f0a9b8). Сервис planner-migrate применяет при up.

## 5. API-контракты (эскиз, детали — в планах фаз)

- `GET /api/calendar/month?year=&month=` → по дню: count, max_priority, has_overdue.
- `GET /api/tasks?scope=&date=&sort=time|priority` → карточки дня (расширение существующего getTasks).
- `GET/POST/PATCH/DELETE /api/goals` + `GET /api/goals/{id}/progress`.
- `GET/POST/PATCH/DELETE /api/habits`, `POST /api/habits/{id}/log`, `DELETE /api/habits/{id}/log?date=`.
- `GET /api/tracking/heatmap?year=` → [{date, done_count}].
- `GET /api/tracking/summary?range=day|week|month` → {done, total, by_sphere, trend}.
- `GET /api/tracking/log?range=` → закрытые задачи группировкой по дням.
- (Волна 5) `POST /api/ai/chat` → копайлот с контекстом.

## 6. Команда-строитель (агентский ростер, по образцу проекта Здоровье)

Персистентный ростер в `planner-v2/.claude/agents/`, переиспользуемый между сессиями. Claude (CEO/координатор) оркеструет через Workflow tool по волнам. Каждый агент = `<name>.md` с frontmatter (name, description, tools) и system-промптом (роль, что читает, контракт output, стиль).

| Агент | Роль | Tools |
|-------|------|-------|
| **architect** | Бьёт фичу на контракты API + схему БД, ревьюит границы модулей, решает миграции | Read, Grep, Glob, Bash |
| **backend** | FastAPI-эндпоинты, SQLAlchemy-модели, Alembic-миграции, pytest | Read, Write, Edit, Bash, Grep, Glob |
| **frontend** | React/TS экраны и компоненты по DESIGN.md, api.ts, типы | Read, Write, Edit, Bash, Grep, Glob |
| **designer** | Визуал таймлайна/плотности/трекинга, Air-Bank стиль, anti-AI-slop, токены/CSS | Read, Write, Edit, Grep, Glob |
| **qa** | Тесты, headless-верификация через серверный initData-скрипт в контейнере | Read, Write, Edit, Bash, Grep, Glob |
| **reviewer** | Адверсариальное ревью диффа перед merge: контракты, безопасность, регрессии | Read, Bash, Grep, Glob |

Координатор (CEO) сам не пишет код в волнах — раскладывает задачи, сводит, гейтит merge. Оркестрация: на каждую волну Workflow с pipeline (architect → backend ∥ frontend → qa → reviewer), адверсариальная верификация перед деплоем.

## 7. Волны постройки

Цель — полный продукт. Волнами ради параллелизма команды и того, что каждая волна = рабочий деплой (не один неоткатываемый коммит).

1. **Фундамент IA** — 5-таб скелет (BottomTabs), слияние Задачи+Проекты+Drawer → таб «Списки», перенос Day-view в таб «Сегодня» (гибрид: таймлайн + «без времени» + Inbox + сводка).
2. **Календарь-плотность** — месяц-грид с нагрузкой/приоритетом → drill в день с карточками (сорт время/приоритет), тогл Неделя/Месяц.
3. **Трекинг** — теплокарта года + дашборд метрик + лента-ретро + привычки (новые модели Habit/HabitLog).
4. **Цели** — модель Goal + экран целей с прогрессом и связью с задачами.
5. **AI-копайлот** — разговорный слой поверх всего контекста планнера.

> **Порядок волн — на ревью пользователя.** Возможна перестановка (например, Трекинг раньше Календаря как флагманская фича). Зафиксировать перед первой волной.

## 8. Верификация (как Здоровье — дисциплина)

- Прод Mini App нельзя открыть headless (Telegram initData auth). Серверная верификация: python-скрипт в контейнере подписывает initData боевым токеном из .env и дёргает API на localhost:8000.
- Визуальную проверку Mini App делает пользователь (память: visual-verify-before-claim-done — не верить deploy hash).
- Каждая волна: pytest зелёные + серверный smoke + визуальный ОК пользователя перед закрытием.
- Деплой/пуш — только с подтверждения пользователя.

## 9. Риски и ограничения

- **Стопка sheet'ов / z-index** — известный долг composer'а, не плодить в новых экранах. Рассмотреть порталы.
- **Привычки и AI-копайлот** — крупные отдельные куски, реалистично последние волны.
- **Контекст-бюджет команды** — каждый агент читает только свою зону (architect отдаёт контракты, остальные не читают весь репозиторий).
- **Регрессии при слиянии табов** — Drawer/ListView активно используются; reviewer обязателен на волне 1.
- **Priority mapping** — UI-мокапы показывали P1–P4, в БД none/low/medium/high. Зафиксировать единый маппинг на волне 1 (none=P4 … high=P1 или ввести 4-уровневую шкалу).
- **«Сегодня» дублирует Календарь-день** — переиспользовать один компонент таймлайна для обоих, не копировать.

## 10. Решения, зафиксированные в брейнсторме

| Вопрос | Решение |
|--------|---------|
| Структура навигации | 5 табов: Сегодня / Календарь / Списки / Цели / Трекинг |
| Задачи + Проекты | Слить в один таб «Списки» (смарт-вью + дерево проектов), Drawer убрать |
| Цели | Отдельный таб (строить с нуля) |
| Сегодня | Гибрид (таймлайн + без-времени + Inbox + сводка), не чистый Day-view |
| Трекинг = «календарь-трекинг» | Все 4: теплокарта + дашборд + ретро + привычки |
| Календарь | Месяц-плотность (Ledger-стиль) → drill в день с карточками |
| Объём | Полный продукт, не MVP-урезка |
| Команда | Персистентный ростер .claude/agents (6 ролей) + оркестрация Workflow по волнам |
| Порядок волн | На ревью (по умолчанию 1→5 как в секции 7) |

## 11. Вне скоупа этого спека

- Реальная доставка напоминаний (reminder_at) — cron-шедулер в боте (отдельная фаза Ф4, отложено).
- Движок авто-генерации повторов (recurrence хранится, генерация — Ф4).
- Незакоммиченные правки в `planner-bot/` (старый v1 NocoDB-бот): unified /find + open-callback + error-handler — закоммитить отдельным коммитом, к этой переделке не относится.
- Мультиязычность, шифрование, экспорт.
