# Переделка пикера «Дата/время» (TickTick-стиль) + синк quick-add

> Дата: 2026-06-14. Статус: дизайн утверждён владельцем (мокап «мне нравится»).
> Мокапы: `база-проекта-v3/pages/T1-datetime.html` (A одиночный день, B многодневный),
> `база-проекта-v3/pages/T1-quickadd.html` (быстрое поле — синк текущей реальности).

## Проблема
Текущий `DateSheet` = две вкладки **Дата / Длительность**. Вкладка «Длительность»
(чипы 15м/30м/1ч/1.5ч/2ч) бесполезна, пока не задано время начала на вкладке «Дата»,
и показывает гейт «Сначала задай время начала». Раздражает.

## Решение — единый пикер «Дата/время» (без вкладок)
Один экран (bottom-sheet), TickTick-модель «старт → дедлайн»:
- **Весь день** — тумблер. Вкл → строки времени скрыты, длительность в днях.
- **Календарь месяца + heat** (g/y/r по нагрузке дня, как в `DateJumpSheet` через `getDensity`).
  Тап дня = ставит **начало**; тап дня дальше = **дедлайн**, спан между подсвечивается.
- **Начало**: дата (из календаря) + время (опц., пилюля → колесо/инпут).
- **Дедлайн**: дата + время (опц.). Может быть **другой день** (многодневный спан).
- **Длительность** — производная-метка («1 ч 30 мин» / «4 дня»). НЕ вкладка, НЕ требует ввода первым.
- **Напоминание** + **Повтор** — как сейчас, в этом же шите.
- **Готово** — применяет всё.

## Изменение модели (backend)
Task сейчас: `due_date`, `due_time`, `end_time` (Time, тот же день). Нет конца-даты.
- **+`Task.end_date: date | None`** (миграция add-column, безопасно).
- Семантика: старт = `due_date`+`due_time`; дедлайн = `end_date`(или `due_date` если null)+`end_time`.
- Обратная совместимость: у старых задач `end_date=null` → конец в тот же день через `end_time` (как было).
- ZERO-AFK не затронут (поля пишет клиент).

## API
- `TaskOut` / `TaskIn` / `TaskPatch` / `_TASK_FIELDS` (+ create payload): `+end_date`.
- `DateValue` (фронт) `+end_date: string | null`.

## Frontend
- `DateSheet` переписать: убрать `seg`-вкладки + блок «Длительность» (DURATIONS) + гейт.
  Рендер: тумблер весь-день → календарь(heat) → строка Начало → строка Дедлайн → метка длительности
  → Напоминание → Повтор → Готово.
- Логика выбора в календаре: первый тап = начало; следующий тап позже начала = дедлайн;
  тап раньше начала = новое начало (сброс дедлайна). Спан-подсветка ячеек между.
- Время: тап пилюли времени → существующий time-инпут/колесо (как было в `DateSheet`).
- Длительность-метка: считать из (start, end); дни если разные даты, иначе часы/минуты.
- `onApply` отдаёт `DateValue` с `end_date`.

## Таймлайн (отображение)
- Один день (start/end в одну дату) → блок как сейчас (по `due_time`–`end_time`).
- Многодневный (end_date > due_date) → показ в all-day-баре как спан-чип (см. teardown «cross-day спан-бары»).
  **Скоуп:** в ЭТОЙ сборке многодневное сохраняется и показывается чипом в all-day; полноценные
  горизонтальные спан-бары на таймлайне — следующий шаг (не блокирует).

## Quick-add (уже построено, мокап = документация)
`T1-quickadd.html` фиксирует текущую реальность (не переделывается):
- «+» открывает ЕДИНСТВЕННОЕ поле «Быстрая задача» БЕЗ клавиатуры (фокус не на инпуте).
- Чипы: дата · проект · приоритет · тег · напоминание — рабочие, пикеры инлайн (z-index>оверлея).
- Чип «дата»/«напоминание» открывают новый пикер «Дата/время».
- NL-подсветка токенов; тап токена → назад в текст. Стрелка ↑ — создать.
- Убрано: «Развернуть», полный composer, autofocus, быстрые-чипы даты.

## Тесты (гейт)
- vitest: чистая функция длительности (start,end)→метка (дни/часы/минуты); выбор начало/дедлайн в календаре.
- pytest: round-trip `end_date` (create/patch/out), null-совместимость.
- e2e: пикер открывается, тап дня ставит начало, второй день → дедлайн+спан, время-пилюля, Готово применяет.
- Визуал-baseline пикера (обновляет владелец).

## Вне скоупа (follow-up)
- Горизонтальные многодневные спан-бары на вертикальном таймлайне.
- Колесо-time вместо инпута (если текущий ввод времени ок).
