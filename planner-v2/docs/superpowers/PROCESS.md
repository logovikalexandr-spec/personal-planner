# Рабочий процесс planner-v2 — «Глубина сначала»

> Зафиксировано 2026-05-30 после ретро. Проблема прошлого подхода: быстрые и широкие, но мелкие — фичи выходили на happy-path, дыры (состояния, edge, несогласованность) находил пользователь. Этот процесс ставит ГЛУБИНУ перед кодом и снимает «пинок» с пользователя.

## Роли пользователя и AI
- **Пользователь** (CEO, не технарь): проверяет работу, даёт направление, рулит по мокапам. НЕ пишет ТЗ, НЕ ловит дыры, НЕ микроменеджит пиксели.
- **AI** (CEO-координатор + agent-team): автономно доводит фичу до глубины, объясняет ПРОСТО и ВИЗУАЛЬНО, находит дыры сам.

## Пайплайн фичи (3 фазы)

### Фаза 1 — РАЗВЕДКА (мокапы, БЕЗ кода) ← новое, главное
Агент `product-depth` выдаёт **deep-спеку**, всё показывается мокапами в браузере. **ВСЕГДА `open` мокапы локально** ([[feedback-open-mockups-local]]), не только PNG-в-чат.
0. **Сверка с реестром паттернов** — прочитать `.claude/PATTERNS.md`; новая фича переиспользует существующий паттерн или осознанно вводит новый (тогда добавить в реестр).
1. **Карта флоу** — каждый тап → что происходит, что открывается/закрывается.
2. **Матрица состояний** — пусто / загрузка / ошибка / выбрано / частично / край.
3. **Edge-охота + гипотезы** — «а что если»: двойной тап, отмена, вложенность, конфликт жестов, стопка шторок.
4. **Аудит согласованности** — новое поведение = как уже работающее (одна сущность ведёт себя одинаково везде).
5. **Reuse-карта (отдельный HTML)** — где ещё эта фича/паттерн/компонент должны использоваться по всему приложению. Фича прорастает консистентно везде, не живёт в одном месте.
6. **Развилки** — где 2+ разумных поведения → короткий вопрос пользователю (фича-уровень).

**Итеративно (не пакетом):** показывать пользователю по ходу — сначала карта флоу + развилки, дать порулить РАНО, потом состояния/reuse с учётом его правок. Не копить всё до конца. Дешёвая правка направления > переделка готового пакета.

→ Пользователь смотрит мокапы, рулит, утверждает. **Кода ещё нет.**

### Фаза 2 — СБОРКА до глубины
Код покрывает ВСЮ матрицу состояний + закрытые edge из Фазы 1. НЕ happy-path. designer даёт визуал по DESIGN.md, frontend/backend строят. Переиспользуют паттерны из `PATTERNS.md`, выносят общую логику в `lib/` (не плодят копии).

### Фаза 3 — РЕВЬЮ + ДОКАЗАТЕЛЬСТВО ПОВЕДЕНИЯ (гейт глубины)
- `reviewer`: неполная матрица состояний / несогласованность поведения = **BLOCK** (не minor).
- **Behavior-proof (реальная проверка, не только код-ревью):** frontend строит локальную harness-страницу (компонент + мок-данные + мок `tg()`), `browse` headless прогоняет КАЖДОЕ состояние/edge (клик→скриншот) → лист доказательств PNG. `open` локально пользователю. Так все состояния проверены живьём, БЕЗ ручного жамканья каждого кейса пользователем и без прод-auth Telegram.
- Обновить `BACKLOG.md` (статус глубины фичи) и `PATTERNS.md` (если ввели/изменили паттерн).
- Деплой — гейт пользователя. Финальный визуал в Telegram — за пользователем.

## Принципы
- **Глубина > ширина.** Одна фича до дна лучше пяти каркасов.
- **Визуально и просто.** Пользователь не технарь — всё на мокапах, словами поведения.
- **Без микроменеджмента.** Разговор на уровне флоу/состояний, не отступов.
- **Без пинка.** Дыры находит product-depth, не пользователь.
- **Согласованность.** Одна сущность — одно поведение во всём приложении.

## Реестры (живут постоянно, обновляются каждой фичей)
- **`.claude/PATTERNS.md`** — глобальный реестр UX-паттернов (как ведёт себя single-select picker, шторка, дерево, кант приоритета). Источник согласованности по ВСЕМУ приложению. Фаза 1 сверяется, Фаза 3 обновляет.
- **`docs/superpowers/BACKLOG.md`** — реестр всех фич + статус глубины (каркас / happy-path / докручено до дна). Видно картину целиком и что недокручено.

## Команда (ростер `.claude/agents/`)
architect · backend · frontend · designer · **product-depth** (новый, Фаза 1) · qa · reviewer (усилен на глубину). Оркестрация — Workflow по фазам. Кастомные роли в Workflow задаются ПРОМПТОМ (agentType-реестр их не видит).
