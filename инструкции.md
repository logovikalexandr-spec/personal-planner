# Personal Planner — инструкции

> Главный контекстный файл проекта. Claude читает после `CLAUDE.md` в начале сессии.

## Суть проекта

Personal Planner — личный таск-менеджер уровня TickTick для одного владельца.
Интерфейс — Telegram Mini App (быстрый, тактильный, нативный) + бот-обёртка.
Не «ещё один todo», а ежедневный рабочий инструмент: задачи, проекты, календарь,
цели и трекинг привычек в одном плотном тёмном приложении.

Активная версия — `planner-v2/`. `planner-bot/` — прототип v1, оставлен как архив.

## Философия

1. **Daily-app, не лендинг.** Плотный, спокойный, предсказуемый. Скорость и тактильность
   важнее украшательства. Открыл — за секунды записал/закрыл задачу.
2. **UI-first.** Сначала живой mock UI → согласование с владельцем → потом бэкенд.
   Владелец рулит видом приложения, не догадывается о нём по коду.
3. **Depth, не happy-path.** Фича готова, когда покрыта матрица состояний (пусто/загрузка/
   ошибка/edge), а не только идеальный путь. Дыры находит команда, не пользователь.
4. **Визуал — финальный гейт.** «Готово» = открыли в браузере/Telegram и увидели, что
   работает и выглядит по DESIGN.md. Не верить деплой-хэшу.

## Ключевые ограничения

- **Single-user.** Только задачи владельца. Без мультитенантности, биллинга, онбординга.
  Бот отвечает только `OWNER_TELEGRAM_ID` (allow-list).
- **Бесплатный / OSS стек.** Без платных подписок и SaaS-замков.
- **Один вьюпорт.** Mobile-first Telegram Mini App, без горизонтального скролла.
- **Solo + Claude Code.** Стек под одного разработчика: минимум DevOps, без bloat.

## Информационная архитектура (5 табов)

1. **Сегодня** — гибрид: задачи на сегодня + быстрый ввод.
2. **Календарь** — День/Неделя/Месяц.
3. **Списки** — проекты/папки, дерево (clamp глубины 3), drag, контекст-меню.
4. **Цели** — цель = трекер прогресса.
5. **Трекинг** — привычки/метрики.

## Дизайн

Тёмная TickTick-эстетика: onyx-холст (#0F0F11), единственный ember-акцент (#EE8A3C),
Geist / Geist Mono, плотные строки задач, bottom-tabs. Полный контракт —
`planner-v2/DESIGN.md`. Anti-patterns: emoji в UI, #000000, неон/glow, круглые спиннеры
(только скелетоны), 3-колоночные карточки, AI-клише в текстах.

## Процесс разработки (agent-team)

Сборка волнами через Workflow. С пользователем говорит только **CEO-координатор**;
агенты общаются артефактами (спека/контракт/отчёт). Три фазы на фичу:

1. **РАЗВЕДКА** — product-depth даёт deep-спеку + reuse-карту → designer рисует мокапы →
   CEO показывает пользователю (он утверждает). Без кода.
2. **СБОРКА** — architect фиксирует контракты API+схему → backend ∥ frontend пишут код
   по всей матрице состояний → designer даёт визуал-токены по DESIGN.md.
3. **ГЕЙТ** — qa гоняет состояния/edge → reviewer ставит MERGE/BLOCK по глубине →
   CEO деплоит → пользователь даёт финальное визуальное ОК.

Ростер и правила — `planner-v2/.claude/TEAM.md` и `PATTERNS.md`.

## Правила работы

1. **План перед действием** для нетривиальных изменений. 2-3 варианта, если развилка.
2. **UI-first** для Mini App: mock → согласование → бэк.
3. **Depth-гейт.** Не мержить happy-path без матрицы состояний и reuse-карты.
4. **Визуальная проверка перед «готово».** Открыть живьём, не верить хэшу деплоя.
5. **Общие файлы** (`theme.css`, `App.tsx`, иконки) — строго последовательно (параллель = гонка).
6. **Перед деструктивом** — подтверждение владельца.
7. **Секреты — только в `.env`** (не коммитится). Никаких токенов в коде.
8. **Lazy load памяти** — по воронке и wikilinks, не целыми доменами.

## Definition of Done фазы/волны

- Код покрывает матрицу состояний (пусто/загрузка/ошибка/edge), не только happy-path.
- Тесты зелёные (pytest backend; frontend — что есть).
- reviewer: MERGE (не BLOCK). qa: критичные пути пройдены.
- Задеплоено на prod И визуально проверено владельцем.
