## 1. Проблема и цель

### Проблема
v1 (planner-bot) — рабочий, но: завязан на NocoDB + git-markdown, рассчитан на двух пользователей с ACL, модель задач = только матрица Эйзенхауэра, нет визуального интерфейса (только текст/кнопки в Telegram), голосовой ввод не используется. Планировать в нём неудобно, нет календаря, привычек, целей, нет нормального UI.

### Цель
planner v2 уровня Ledger: личный life-OS для одного пользователя. TickTick-подобный таск-менеджер в виде Telegram Mini App + бот для быстрого захвата + AI-копайлот, который держит контекст всего планнера и помогает планировать. Пользователь планирует сам, AI подсказывает (что забыл, как по времени, как продуктивнее) и по запросу составляет план, который пользователь правит.

### Не-цели
- Не мультиюзер. Никакого ACL, shared/private, мультитенантности.
- Не голосовой ввод (убран совсем).
- Не Obsidian/markdown/git слой (пользователь файлы руками не правит).
- Не замена Claude Code — planner принимает итоги сессий, но не ведёт разработку.

## 2. Принципы

1. Single-user. Вся модель прав упразднена. Один владелец.
2. Mini App — единственная поверхность. Всё состояние в Postgres. Нет markdown/git/Obsidian.
3. Zero manual writing. Пользователь не пишет файлы руками. Ввод = реплика боту или действие в Mini App.
4. Inbox-first. Inbox — дефолтный сборник всех новых задач (как в TickTick): и ручной ввод, и AI-парсинг. Задача без проекта живёт в Inbox.
5. Пользователь у руля планирования. AI — копайлот, не автопилот. Необратимое — с подтверждением.
6. AI не пишет SQL напрямую. Только через типизированные API/tools (защита от галлюцинаций).
7. Free-stack по возможности. LLM стартует на бесплатных моделях (Groq/Gemini), Claude подключаем позже при нехватке качества.
8. Phase-gate. Следующая фаза не начинается, пока DoD текущей не выполнен.

## 3. Модули

| Модуль | Суть |
|--------|------|
| Inbox | Дефолтный сборник новых задач (ручной ввод + AI-парсинг). Триаж в проекты. |
| Задачи (Tasks) | Списки/проекты, теги, 4 приоритета, подзадачи/чеклисты, повторяющиеся, напоминания. Виды: список, smart-списки, матрица Эйзенхауэра. |
| Календарь | День/неделя/месяц, задачи на слоты времени (time-blocking). |
| Цели (Goals) | Большая цель -> прогресс в %, разбивается на задачи. Привычки вложены внутрь целей. |
| Привычки (Habits) | Трекер со streak, периодичность. Живут внутри Целей. |
| Проекты/заметки | Контейнеры задач + заметки (knowledge). |
| AI-копайлот | Разговорный ассистент со знанием полного контекста планнера. |
| Session Intake | Захват итога рабочей сессии -> AI декомпозирует в задачи/план -> Inbox. |

## 4. Архитектура

### Стек

| Слой | Выбор | Обоснование |
|------|-------|-------------|
| Хостинг | Hetzner VPS (существующий) | Уже оплачен, рядом Ledger/NocoDB |
| Бэкенд API | FastAPI | Как Ledger, async, типизация (pydantic v2) |
| БД | Postgres | Источник истины, всё состояние |
| ORM/миграции | SQLAlchemy 2.x + Alembic | Как Ledger |
| Бот | aiogram 3.x | Как Ledger (не python-telegram-bot). Захват + диалог с AI |
| Mini App | React + TypeScript + Vite | Ledger использует vanilla TS, но у planner UI сложнее (drag-календарь, много видов, трекер) -> React оправдан. Vite base=/app/, dev proxy /api -> :8000 |
| Mini App serving | FastAPI отдаёт собранный frontend/dist как статику (MINI_APP_DIST_DIR) | Как Ledger prod |
| Reverse proxy / TLS | Caddy + sslip.io | HTTPS БЕЗ покупки домена: <ip-с-дефисами>.sslip.io резолвится в IP, Caddy авто-выпускает Let's Encrypt. Решает "нужен поддомен" бесплатно |
| LLM gateway | LiteLLM | Единый интерфейс к провайдерам, как Ledger |
| Типизированные AI-tools | Pydantic AI | Агент не пишет SQL, только типизированные tools |
| LLM (старт) | Groq free + Gemini free (через LiteLLM) | Бесплатная классификация и парсинг |
| LLM (позже) | Claude (Anthropic) | Разговорный копайлот, если free не тянет |
| Очередь/планировщик | APScheduler (+ Redis/arq опц.) | Проактив/напоминания, как Ledger |
| Логи | structlog | Как Ledger |
| Деплой | Docker Compose (postgres + redis + migrate + api + bot + caddy) | Как Ledger prod-стек |
| Таймзона | Europe/Prague | |

### Высокоуровневая схема

```
Telegram (бот + Mini App webview)
        |
        | HTTPS (Caddy, planner.<домен>)
        v
FastAPI backend  ----  Postgres (источник истины)
        |
        +-- LLM провайдер (Groq/Gemini -> позже Claude), типизированные tools
        |
        +-- python-telegram-bot (захват, диалог, JobQueue проактив)
        |
        +-- ingest endpoint (для /wrapup и Session Intake)
        |
        +-- хранилище вложений (диск VPS или Telegram file_id)
```

### Раскладка кода (по образцу Ledger src/)

```
planner-v2/
  src/planner/
    core/        # конфиг, безопасность, общие утилиты
    db/          # SQLAlchemy модели, сессии
    api/         # FastAPI роутеры (tasks, projects, goals, habits, notes, inbox, ai, ingest)
    bot/         # python-telegram-bot хендлеры, диалог, JobQueue
    agents/      # LLM: парсинг, классификация, копайлот, типизированные tools
    services/    # бизнес-логика (task service, planning service, intake service)
  alembic/       # миграции
  frontend/      # React + TS + Vite Mini App
  docker-compose.yml
  Caddyfile
  pyproject.toml
```

### Инварианты
1. Postgres — источник истины. Всё остальное производное.
2. AI работает только через типизированные tools/API, не пишет SQL.
3. Необратимые операции — только с подтверждением (inline-кнопки / диалог в Mini App).
4. Секреты только в `.env` (не в git, не в логах).
5. Single-writer на уровне бота сериализует TG-события (asyncio).
6. Mini App аутентифицируется через Telegram WebApp initData (проверка подписи на бэке).

## 5. Модель данных (Postgres)

Черновик сущностей. Точные поля/типы финализируются в плане.

### `project` (он же list/контейнер)
- id, name, slug, color, icon, parent_id (для вложенности папок), is_inbox (bool, единственный Inbox), archived, created_at.

### `task`
- id, title, description, project_id (NULL -> Inbox), priority (none/low/medium/high), 
- due_date (date, nullable), due_time (time, nullable), reminder_at (datetime, nullable),
- recurrence (rule, nullable), status (todo/in_progress/done/archived), done_at,
- eisenhower (computed/derived из priority+due или отдельное поле — решить в плане),
- source (manual/session) — для разделения Inbox "Мои" / "Из сессий",
- order_index, parent_task_id (для подзадач), goal_id (nullable), created_at.

### `tag` + `task_tag` (M2M)
- tag: id, name, color. task_tag: task_id, tag_id.

### `goal`
- id, title, description, target_date (nullable), progress_pct (derived из связанных задач/привычек), status, created_at.

### `habit`
- id, goal_id (nullable, привычка может жить внутри цели), title, periodicity (daily/weekly/custom), 
- target_per_period, color, archived, created_at.

### `habit_log`
- id, habit_id, date, done (bool/count). Для streak-расчёта.

### `note`
- id, project_id (nullable), title, body (markdown-текст в БД, не файл), created_at, updated_at.

### `inbox_item`
- id, kind (manual/text/photo/link/session), source (manual/session), raw_content, parsed_json (предложенные AI поля), 
- status (new/parsed/triaged/archived), suggested_project_id, created_at.
- Триаж превращает inbox_item в task (и опц. note/subtasks).
- source делит Inbox на "Мои" (manual) и "Из сессий" (session/AI-парсинг).

### `repo_link` (экосистема Claude Code)
- id, repo_key (имя папки или git-remote URL), project_id, created_at.
- Связка репозиторий Claude Code -> planner project. Хранится НА СТОРОНЕ planner, не в репо.
- Скилл /planner определяет repo_key текущего проекта и тянет привязку. Первая привязка запоминается.

### `attachment`
- id, task_id (nullable) / note_id (nullable) / inbox_item_id (nullable), 
- kind (photo/link/file), url_or_fileid, meta. Фото/ссылки прикрепляются к задаче.

### `reminder`
- id, task_id, fire_at, sent (bool). Обрабатывается JobQueue.

### `ai_context` / `audit_log`
- ai_context: ключ-значение/longtext — накопленное понимание контекста для копайлота (по проектам/глобально).
- audit_log: запись изменений (автор, before/after) + LLM-вызовы (модель, токены, стоимость) — как в Ledger.

Виды Сегодня / 7 дней / Эйзенхауэр / по тегам — это ЗАПРОСЫ поверх `task`, не отдельные таблицы.

## 6. Пользовательские потоки

### 6.1 Захват через бота
- Пользователь шлёт боту текст / фото / ссылку.
- Создаётся `inbox_item`. AI (free-модель) предлагает поля: title, due, priority, project, tags. Фото/ссылка -> `attachment`.
- Ответ бота: предложенный разбор + кнопки подтверждения. Подтверждение -> создаётся `task` (по умолчанию в Inbox, если проект не назначен).
- Быстрый ручной ввод задачи (без AI) тоже падает в Inbox.

### 6.2 Триаж Inbox
- В Mini App (вход с таба "Сегодня", бейдж-счётчик) или в боте.
- Список `inbox_item`/задач без проекта. Пользователь назначает проект/список, дату, приоритет, теги. AI может предложить.
- Inbox разделён по источнику фильтрами/кнопками: "Мои" (занёс сам) и "Из сессий" (AI напарсил из wrapup/сессий) — чтобы не путаться откуда задача.

### 6.3 Планирование (сердце)
- Пользователь планирует сам в Mini App: списки, перетаскивание в календарь на слоты.
- AI по запросу ("составь план на день/неделю"): раскидывает задачи по времени с учётом приоритетов/дедлайнов/занятости -> показывает -> пользователь правит.
- AI-совет в момент: при добавлении/планировании может подсказать ("вторник свободнее").

### 6.4 AI-копайлот (диалог)
- Floating-кнопка на любом экране Mini App + диалог в боте.
- Разговорный, держит контекст: знает задачи/проекты/привычки/цели/состояние через типизированные tools.
- Примеры: "что я забыл", "перекинь просрочку на завтра", "что по проекту ZIMA", "составь план дня".
- Проактив — мягкий: карточка совета на экране "Сегодня" (+ опц. утренний/вечерний дайджест в боте), без навязчивых пингов. Главный режим — по запросу.

### 6.5 Цели и привычки
- Цель: заголовок + целевая дата + связанные задачи -> прогресс %.
- Привычки внутри цели: периодичность, отметка выполнения, streak.

### 6.6 Session Intake (захват рабочей сессии)
- Источник: вывод `/wrapup` скилла (расширяем) и/или ручной структурный итог.
- Поток: итог сессии -> POST на ingest-эндпоинт (аутентифицированный) -> создаётся `inbox_item` kind=session -> AI декомпозирует: задачи (с приоритетом/датой), план -> `note` проекта, способы реализации -> подзадачи/notes, предлагает проект.
- Пользователь разбирает из Inbox (подтверждение встроено) -> всё падает в planner.
- Отдельного таба в Mini App нет — всё через Inbox.

### 6.7 Интеграция /wrapup
- Скилл `/wrapup` дополнительно к логу в NotebookLM "AI Brain" шлёт структурный итог сессии в planner ingest-эндпоинт.
- Формат итога: задачи + план + способы реализации (+ проект, если известен).

### 6.8 Экосистема Claude Code <-> planner (round-trip)
Planner = центральный хаб задач всех проектов пользователя (ZIMA, Ctok, MR-VLAD, Champ и т.д.).

Петля:
1. Сессия в Claude Code закончена -> `/wrapup` шлёт итог -> planner ingest -> AI декомпозит -> задачи в проект (через Inbox, source=session, фильтр "Из сессий").
2. Пользователь работает в planner: отмечает задачи done, добавляет свои (source=manual, фильтр "Мои").
3. Новая сессия в Claude Code -> скилл `/planner` (проектная сторона) определяет repo_key -> тянет из planner read-API состояние проекта: что сделано / в работе / план -> Claude видит контекст и продолжает осмысленно.

Решения:
- Claude Code сторона ТОЛЬКО ЧИТАЕТ контекст (read-only). Статусы done пользователь ставит сам в planner. Это безопаснее — Claude не ошибётся со статусами.
- Связка репо -> project хранится на стороне planner (`repo_link`), определяется по имени папки / git-remote. Первая привязка запоминается. БЕЗ файлов в репозитории, БЕЗ постоянных коммитов.
- Состояние задач = Postgres planner (через API), не в репозиториях проектов.

Что строить: read/write API planner + токен; новый проектный скилл `/planner` (pull контекста проекта в начале сессии); поле source; фильтры Inbox.

## 7. UI/UX (Mini App, Air-Bank style)

Стиль: чисто, карточки, мягкие цвета, крупные акценты, нижняя навигация. Без AI-эстетики (по user-design-preferences).

### Нижние табы (5)
1. Сегодня — agenda дня: задачи на сегодня + привычки + карточка совета AI + вход в Inbox с бейджем.
2. Календарь — день/неделя/месяц, задачи на слотах времени.
3. Задачи — списки/проекты, smart-списки (7 дней, теги), переключатель вида (в т.ч. матрица Эйзенхауэра).
4. Цели — цели с прогрессом %, привычки/streak вложены внутрь цели.
5. Проекты / заметки — контейнеры + заметки.

AI — floating-кнопка на всех экранах (диалог-копайлот).

Экран Inbox (вход с "Сегодня"): фильтры/кнопки "Мои" и "Из сессий" для разделения по источнику.

### 7.1 Иерархия экранов (что видно первым)
- Сегодня (порядок сверху вниз): (1) дата + одна строка совета AI; (2) блок "Просрочено" — только если есть; (3) задачи на сегодня, по времени; (4) привычки дня (чек-строка); (5) бейдж Inbox в шапке. Принцип: одна вещь важнее всего на экране — сегодняшние задачи.
- Календарь: текущий день/неделя в фокусе, переключатель день/неделя/месяц сверху, задачи-слоты в теле.
- Задачи: переключатель вида сверху (Списки / Smart / Эйзенхауэр), тело — выбранный вид. По умолчанию — список текущего проекта/Inbox.
- Цели: список целей с прогресс-баром; тап в цель -> детали + вложенные привычки.
- Проекты/заметки: список проектов; тап -> задачи проекта + заметки.

### 7.2 Состояния интерфейса (на каждый экран)
| Экран | Loading | Empty | Error |
|-------|---------|-------|-------|
| Сегодня | скелет карточек | "На сегодня пусто. Добавить задачу?" + кнопка + (если есть Inbox) "Разбери Inbox" | "Не загрузилось. Повторить" |
| Inbox | скелет списка | "Inbox пуст. Кидай мысли боту — появятся здесь." | повтор |
| Задачи | скелет | "Список пуст. Новая задача." | повтор |
| Календарь | скелет сетки | день без задач: "Свободно. Запланировать?" | повтор |
| Цели | скелет | "Целей нет. Поставить первую?" | повтор |
| AI-чат | индикатор "печатает" | приветствие + примеры запросов | "AI недоступен, попробуй позже" |
Empty state = фича: тёплый текст + основное действие, не "ничего не найдено".

### 7.3 Storyboard первого запуска
1. Открыл Mini App впервые -> короткий экран-приветствие (1 экран, не тур): "Это твой планнер. Кидай задачи боту или жми +. AI поможет разобрать." -> кнопка "Начать".
2. Пустой "Сегодня" с явным основным действием (добавить / разобрать Inbox).
3. Первая задача -> сразу видна петля: добавил -> в Inbox -> разобрал в проект.

### 7.4 Telegram Mini App ограничения
- Один мобильный вьюпорт (телефон). Дизайн mobile-first.
- Тема (свет/тьма) берётся из Telegram theme params -> CSS-переменные подстраиваются под клиент.
- Учитывать safe-area (вырезы), фиксированную нижнюю навигацию над системной полосой.
- Touch-таргеты минимум 44px. Клавиатура не должна перекрывать активное поле ввода.
- Кнопки подтверждения необратимого — крупные, разнесены, чтобы не промахнуться.

### 7.5 Дизайн-система
DESIGN.md пока НЕТ — это дыра (AI-slop риск). РЕШЕНО: `/design-consultation` гоняем ПОЗЖЕ, на UI-фазе (не сейчас). DESIGN.md как у Ledger: конкретный шрифт, палитра (CSS-переменные), шкала отступов, радиусы, motion. До него "Air-Bank style" — вайб, не контракт. На UI-фазе это блокер качества.

### 7.6 Решённые дизайн-выборы (из дизайн-ревью)
1. Календарь: DRAG задач на слоты обязателен (как TickTick). Не только форма назначения времени.
2. Эйзенхауэр: НЕ отдельный экран. Группировка по приоритету/срочности ВНУТРИ списка задач (вид-переключатель -> режим группировки).
3. AI floating-кнопка: прячется при скролле вниз, возвращается при скролле вверх. По тапу — оверлей-шторка снизу поверх текущего экрана (контекст за ней виден), не отдельный экран. ПОДТВЕРЖДЕНО.
4. Онбординг: при первом запуске — экран как ОБЩИЙ ОБЗОР состояния проектов (overview), а не просто приветствие. Показывает срез по проектам.
5. DESIGN.md: позже, на UI-фазе (см. 7.5).

## 8. Операции

- Деплой: Docker Compose на существующем VPS. Caddy отдаёт Mini App по HTTPS на поддомене planner.<домен>.
- Проактив/напоминания: python-telegram-bot JobQueue (утренний/вечерний дайджест, reminders).
- Бэкап: pg_dump по расписанию (как Ledger). Вложения — rsync/диск.
- Секреты: `.env` на VPS.
- Наблюдаемость: логи + audit_log (LLM-стоимость, изменения).

## 9. Фазы

- Ф0: каркас репозитория по образцу Ledger (FastAPI, Postgres, Alembic, docker-compose, Caddy, бот-скелет, аутентификация Mini App).
- Ф1: ядро задач — модели (project/task/tag/subtask/inbox_item/attachment/reminder), API, бот-захват текст/фото/ссылка -> Inbox, AI-парсинг полей (free LLM), триаж.

- Ф3: Цели + привычки (streak, прогресс) + Проекты/заметки.
- Ф4: AI-копайлот — диалог, типизированные tools, контекст-слой, планирование по запросу, мягкий проактив.

## 11. Глоссарий

- Inbox — дефолтный сборник всех новых задач (ручных и AI-парсенных) до распределения по проектам.
- Session Intake — захват итога рабочей сессии и его AI-декомпозиция в задачи/план.
- Копайлот — разговорный AI со знанием контекста планнера, помогает планировать; не автопилот.
- Эйзенхауэр — вид/представление задач по матрице приоритет-срочность, один из видов, не единственная модель.
