## Цвет за скруглённый угол карточки = overflow:hidden НЕ клипает на дробном transform-слое → clip-path (2026-06-20)
**Симптом:** у тинт/бордюр-карточек (блоки таймлайна `.cal-block`, all-day `.cal-chip`, строки списка `.task-row`/`.task-swipe`) цвет вылезал тонкой ДУГОЙ за правый/левый скруглённый угол на iOS. В списке — красный (слот свайпа «Удалить» за строкой), на таймлайне — тинт/border-left.
**3 ЛОЖНЫХ ФИКСА (вслепую, НЕ повторять):** (1) child сам скругляет фон + radius:0/var; (2) `translateZ(0)` на родителе `.task-swipe`; (3) `translateZ(0)` на самом элементе («промотировать в свой слой»). Все мимо — translateZ сам шов и ПРОВОЦИРУЕТ. `-webkit-mask-image: radial-gradient` тоже НЕ помог.
**КАК ВОСПРОИЗВЁЛ (ключевой приём!):** десктоп-Chromium ОБЫЧНО не показывает (целочисленный сдвиг). Репро: поставить родителю `transform: translate3d(0,-0.37px,0)` (ДРОБНЫЙ — имитирует инерцию скролла `.cal-grid`) + элементу `transform: scale(7)` + зум угла. Тогда `overflow:hidden+border-radius` светит цвет сзади тонкой дугой — видно в Chromium через chrome-devtools (preview-app-mock на vite). Запуск Chrome для MCP: `Google Chrome --remote-debugging-port=9222 --headless=new`, потом navigate.
**ИСТИННЫЙ КОРЕНЬ:** `overflow:hidden` + `border-radius` НЕ обрезает скруглённый угол идеально, когда контейнер на дробно-сдвинутом GPU-слое (composited + non-integer offset). WebKit рисует контент/задний слой на ~1px за радиус.
**ФИКС (подтверждён в репро живьём):** `clip-path: inset(0 round R)` — клипает точно, GPU-аккуратно, угол чистый. Добавлен к `.task-swipe`/`.cal-block`/`.cal-chip` (оставил overflow+radius как fallback). Клипает и задний слой (свайп), и border-left, и тинт.
**Применять:** скруглённая карточка с цветом/задним слоем внутри transform-контекста (GPU-скролл/инерция) на iOS → клип через `clip-path: inset(0 round R)`, НЕ только `overflow:hidden`. Десктоп-репро = дробный `translate3d` на предке + scale-зум. translateZ-промоция НЕ лечит. Связано: [[feedback-visual-verify]].

## iOS-таймлайн: long-press-создание vs нативный скролл vs лупа = трилемма → GPU-transform скролл (2026-06-20)
**Симптом:** long-press-создание задачи на таймлайне Today «не работает ниже now-линии». Долгая сага диагностики.
**ЛОЖНЫЕ СЛЕДЫ (каждый отвергнут замером, НЕ повторять):** now-line (`pointer-events:none` ✓ не виновата) · FAB/таб-бар клиренс (перекрывают лишь низ ~56-130px) · код-гейт по `nowMin` (нет, grep) · «граница=now» = артефакт авто-скролла (тестируемая зона = ниже now) · `user-select:none`+`touch-callout:none` (применяются — computed `none` — но Telegram-WebView лупу НЕ глушат) · `selectstart`/`dragstart` preventDefault (не глушат лупу) · `disableVerticalSwipes` (уже был).
**ИСТИННЫЙ КОРЕНЬ (трилемма iOS WebView):** на ОДНОЙ скролл-поверхности нельзя одновременно: (а) нативный плавный скролл, (б) надёжный long-press, (в) без лупы выделения. iOS либо крадёт удержание под скролл (`pointercancel`=PCANCEL до взвода), либо на hold показывает лупу text/image-выделения. Лупу + перехват глушит ТОЛЬКО `preventDefault` нативного `touchstart` — но он убивает и нативный скролл.
**РЕШЕНИЕ (что в итоге сработало):** **GPU-transform скролл**. `.cal-scroll`(static) = клип-вьюпорт `overflow:hidden` фикс-высоты (ставится из JS = `visualViewport.height - rect.top - 76`); контент `.cal-grid` двигается `transform: translate3d(0,-offset,0)` НА КОМПОЗИТОРЕ (плавно как нативно). Нативный скролл выключен (`touchstart` preventDefault на пустой сетке → лупы нет, iOS не крадёт → long-press надёжен). Драг/инерция — вручную (touch-события → offset, EMA-скорость, momentum `v*=0.95`). Создание (pointer-жест) работает поверх: `gridTop()` через `getBoundingClientRect` учитывает transform → расчёт минут верен (`pointerToMinutes` с scrollTop=0). Прыжок к now = `setOff(nowTopPx - 70)` через `scrollToNowKey`-проп от Today. На блоках/инпуте `touchstart` НЕ глушим (`closest('.cal-block,.cal-draft,input,...')`).
**ПРОМЕЖУТОЧНЫЕ (НЕ хватило):** ручной `scrollTop` (главный поток → лагало); `selectstart`-guard (лупа осталась); CLAIM-после-удержания (PCANCEL до 110мс).
**КЛЮЧ ПЛАВНОСТИ (не очевидно!):** transform сам по себе НЕ убрал лаг — джанк был в **чтении `scrollHeight/clientHeight` на КАЖДЫЙ touchmove** (форсит reflow/layout) + rAF-батч (кадр задержки). Фикс: кешировать `maxOff` (recalc раз на touchstart/resize, НЕ в move) + применять `transform` ПРЯМО в touchmove (без rAF — GPU-transform дешёвый, reflow не нужен). После этого — плавно. Урок: в touch-хот-пути НИКАКИХ layout-reads (offsetHeight/scrollHeight/getBoundingClientRect) — кешируй; и не батчь дешёвые GPU-записи через rAF (добавляет лаг).
**Применять:** Telegram iOS WebView + кастомный long-press на скролле = делай клип-вьюпорт + `translate3d` на композиторе, не борись с нативным скроллом. Десктоп-мышь НЕ репродит touch-перехват/лупу — слать сборку на устройство владельцу (быстрый цикл rsync→build→up). На каждой неудаче — добавлять on-screen дебаг (копит последние строки), владелец читает трейс `DOWN/CLAIM/ARMED/PCANCEL`. Связано: [[planner-now-line-pointer-bug]], [[feedback-visual-verify]].

## Десктоп-preview ≠ iOS: клава/visualViewport/focus (2026-06-20)
**Грабли:** в Telegram (iOS) лист создания проекта улетал вверх при клавиатуре + тап по иконке не открывал эмодзи-клаву. Мой preview в десктоп-хроме показывал «всё ок» — он НЕ воспроизводит iOS-клавиатуру, visualViewport-сжатие, нативный focus.
**Корни+фиксы:**
- Лист `inset:0`+`max-height:85dvh` → при клаве (~40% экрана) верх за экраном. Фикс: Sheet привязан к `visualViewport` (top+height), max-height=vp.height.
- Программный `input.focus()` на `opacity:0`-инпуте iOS игнорит → клава не открывалась. Фикс: реальный input ПОВЕРХ иконки (opacity:0, pointer-events:auto) — прямой ТАП = нативный фокус = клава.
**Применять:** iOS-специфику (клавиатура, focus, safe-area, 100vh vs dvh, position:fixed+keyboard) НЕ верить десктоп-preview — писать защищённо by-construction (visualViewport-sizing, реальный input-оверлей вместо программного focus) И подтверждать у владельца на устройстве. Связано: [[единый-источник-компонент-как-мокап]].

## position:fixed внутри transformed-предка ломается → портал (2026-06-20)
**Грабли:** ⋯-меню/лист проекта (через Sheet) «висели в воздухе» — рендерились внутри `.drawer`, у которой `transform`(slide-анимация)+`will-change:transform`. Любой `position:fixed`-потомок такого предка позиционируется относительно ПРЕДКА, не вьюпорта.
**Фикс:** `Sheet` → `createPortal(.., document.body)` — выходит из transformed-поддерева, fixed резолвится к вьюпорту.
**Применять:** оверлеи/шиты/модалки всегда порталить в body, особенно если предок имеет transform/filter/will-change/contain.

## Telegram WebView глушит window.confirm/alert (2026-06-09)
Нативные `window.confirm`/`alert`/`prompt` в Telegram Mini App WebView НЕ работают (no-op, confirm→false). Симптом был: «Удалить» → подтверждение есть, но ничего не происходит. Всегда использовать `tg().showConfirm(msg, cb)` / `showAlert` (Telegram WebApp SDK), с фолбэком на window.* для браузера/харнеса. Хелпер `confirmDelete` в TaskDetail.tsx.

## Жест-создание на скролл-контейнере: long-press-гейт обязателен (2026-06-09)
Если жест создания (тап/драг по сетке) перехватывает pointermove сразу — ломается нативный скролл таймлайна («экран колдоёбит, ничего нельзя»). Решение: создание-протяжка только после long-press (как перенос блоков); обычный драг = скролл; тап = быстрое создание. scroll-lock body:fixed для ИНЛАЙН-элемента (в потоке) НЕ нужен — он рвёт экран; нужен только для оверлеев. scrollIntoView нельзя вешать в ref-колбэк (зовётся каждый ререндер → прыжки на каждый символ).

## Гейт пропускает CSS-коллизии классов — нужен визуал-диф (2026-06-20)
**Грабли:** легенда Ганта (T3) на проде рисовала серые круги поверх свотчей. Корень: класс `sw` в Gantt.tsx совпал с глобальным `.sw` (toggle-свитч), чей `::after` = серый круг-knob (19×19, radius:50%) налезал на каждый свотч. Чинил переименованием `sw`→`gsw` (T3-scoped).
**Почему гейт пропустил:** функц-e2e ходит по `data-testid` (текст легенды на месте → зелено), `lint:tokens` не видит коллизий селекторов. Баг чисто визуальный → ловится ТОЛЬКО diff мокап↔рендер глазами/vision.
**Применять:**
1. **Перед «готово» — визуал-свип всех вкладок** через chrome-devtools: preview-<x>-mock рядом с мокапом. Это последняя миля конвейера, она НЕ автоматизирована (Track-2 vision-судья = TODO).
2. **Generic-имена классов = мина.** `sw`/`it`/`tg`/`dot` в новом экране могут совпасть с глобальными. Скоупить под экран (`gsw`, `.t3 .x`) ИЛИ грепать глобал перед использованием.
3. **GOTCHA повторилась:** playwright reuseExistingServer:true + стейл-vite чужого worktree на :5173 → тестит ЧУЖОЕ дерево (22 ложных фейла). Убивать `lsof -ti :5173` чужих worktree перед e2e.
