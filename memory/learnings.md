## Preview-моки врут — аудит ТОЛЬКО по реальному app со всеми входами (2026-06-20)
**Грабли:** свип по preview-мокам показал «всё чисто», а владелец прислал скрин реального Telegram — список «Все» в хлам (кнопки свайпа просвечивали поверх текста). Причина: (1) смотрел только дефолтные табы, не заходил в смарт-списки/проекты/DETAIL; (2) preview-app-mock не рендерил вид «Все» с реальными данными.
**3 реальных дефекта, что вылезли при заходе глубже:**
1. `TaskItem` фон строки `${color}22` (13% alpha) → слоты свайпа просвечивали (везде, где список со свайпом + цвет проекта). Фикс: тинт слоем поверх opaque `var(--surface)`.
2. Нет error-boundary → краш любого компонента = белый/чёрный экран на весь app (боль владельца). Фикс: `ErrorBoundary` на корне.
3. `TaskDetail` мапил вложенные массивы без guard (бэк отдаёт [], но частичные данные = краш). Фикс: `?? []`/`?.`.
**Применять:**
- **Аудит = реальный app, ОБХОД ВСЕЙ матрицы входов:** 6 смарт-списков · каждый проект+⋯ · 5 табов×под-виды · тап карточки→DETAIL · свайп/create/шиты · пусто/ошибка. Не дефолтный таб.
- preview-mock должен мокать ВСЕ эндпоинты экрана (вкл. `/tasks/{id}` detail) — иначе слепая зона.
- Цвет-тинт ПОВЕРХ непрозрачной базы, не replace (полупрозрачный фон над слоями = просвет).
- Связано: [[единый-источник-компонент-как-мокап]].

## Telegram WebView глушит window.confirm/alert (2026-06-09)
Нативные `window.confirm`/`alert`/`prompt` в Telegram Mini App WebView НЕ работают (no-op, confirm→false). Симптом был: «Удалить» → подтверждение есть, но ничего не происходит. Всегда использовать `tg().showConfirm(msg, cb)` / `showAlert` (Telegram WebApp SDK), с фолбэком на window.* для браузера/харнеса. Хелпер `confirmDelete` в TaskDetail.tsx.

## Фронтовая кнопка ≠ есть бэкенд-эндпоинт (2026-06-09)
Кнопка удаления слала DELETE /api/tasks/{id}, которого В БЭКЕНДЕ НЕ БЫЛО (был только delete_checkitem). Фронт `deleteTask` существовал, роут — нет → 404 → reqVoid throw → тихо. Урок: при «кнопка не работает» проверять, что роут/сервис реально реализованы на бэке, а не только api.ts-обёртка. grep по routes/ + services/.

## Жест-создание на скролл-контейнере: long-press-гейт обязателен (2026-06-09)
Если жест создания (тап/драг по сетке) перехватывает pointermove сразу — ломается нативный скролл таймлайна («экран колдоёбит, ничего нельзя»). Решение: создание-протяжка только после long-press (как перенос блоков); обычный драг = скролл; тап = быстрое создание. scroll-lock body:fixed для ИНЛАЙН-элемента (в потоке) НЕ нужен — он рвёт экран; нужен только для оверлеев. scrollIntoView нельзя вешать в ref-колбэк (зовётся каждый ререндер → прыжки на каждый символ).

## Гейт пропускает CSS-коллизии классов — нужен визуал-диф (2026-06-20)
**Грабли:** легенда Ганта (T3) на проде рисовала серые круги поверх свотчей. Корень: класс `sw` в Gantt.tsx совпал с глобальным `.sw` (toggle-свитч), чей `::after` = серый круг-knob (19×19, radius:50%) налезал на каждый свотч. Чинил переименованием `sw`→`gsw` (T3-scoped).
**Почему гейт пропустил:** функц-e2e ходит по `data-testid` (текст легенды на месте → зелено), `lint:tokens` не видит коллизий селекторов. Баг чисто визуальный → ловится ТОЛЬКО diff мокап↔рендер глазами/vision.
**Применять:**
1. **Перед «готово» — визуал-свип всех вкладок** через chrome-devtools: preview-<x>-mock рядом с мокапом. Это последняя миля конвейера, она НЕ автоматизирована (Track-2 vision-судья = TODO).
2. **Generic-имена классов = мина.** `sw`/`it`/`tg`/`dot` в новом экране могут совпасть с глобальными. Скоупить под экран (`gsw`, `.t3 .x`) ИЛИ грепать глобал перед использованием.
3. **GOTCHA повторилась:** playwright reuseExistingServer:true + стейл-vite чужого worktree на :5173 → тестит ЧУЖОЕ дерево (22 ложных фейла). Убивать `lsof -ti :5173` чужих worktree перед e2e.
