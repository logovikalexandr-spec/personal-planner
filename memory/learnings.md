# Learnings — инсайты и грабли

> Что узнали по ходу. Одна запись = один урок. Линкуй `[[решения/X]]`.

## 2026-06-23
- **PWA pull-to-refresh НЕ делать через `location.reload()`.** Полный reload fixed-bottom-bar PWA на КОРОТКИХ (не-скроллящихся) табах в iOS standalone сдвигает `position:fixed; bottom:0` навбар ВВЕРХ (пост-reload iOS-транзиент). Чинить позицию бесполезно (visualViewport-анкер фиксит лифт, но дрожит на scroll-событиях; preventDefault мимо). Решение: **мягкое in-app обновление данных** (событие `planner:refresh` → экраны перечитывают `load()` через `useRefreshSignal`), новый код — на cold-start (network-first SW). Без reload навбар физически не двигается.
- **iOS-специфику НЕ дебажить вслепую в CDP.** chrome-devtools (desktop) не репродит iOS safe-area / rubber-band / momentum. Несколько фиксов вслепую (overscroll-behavior, vv-анкер, preventDefault) провалились. Развязка: (1) точный симптом от владельца («ПОСЛЕ pull-to-refresh ПОДЛЕТАЛА строка» ≠ «дрожит при касании»), (2) дебаг-оверлей реальных чисел вьюпорта (iH/vvH/safe-area/tbBot/latched MAXLIFT) на устройстве. Замер опроверг гипотезу «лифт» (MAXLIFT=0 в покое) и направил на reload.
- **После деплоя проверяй SERVED бандл, не только «build ок».** Сборка агента/докера может не пересобрать образ (кэш) → служит старый бандл. `curl …/app/ | grep index-*.js` + сверить хэш сменился.
- **zsh НЕ word-split'ит unquoted переменную** (в отличие от bash): `for f in $FILES` → одна строка. Использовать массив `files=(...)` + `"${files[@]}"`.
- **Молчащий `catch` = потерянные данные юзера.** measure-метрика глотала ошибку POST → провал выглядел как успех (данные не сохранялись на старом кэш-бандле). Всегда показывать ошибку записи.

## НЕ кликать деструктивные кнопки на ПРОДЕ через chrome-devtools (headless авто-принимает confirm) (2026-06-21)
**Что случилось:** проверял удаление в chrome-devtools на ЖИВОМ проде, скриптом кликал кнопки «Удалить». (1) `evaluate_script` по умолчанию `dialogAction:accept` → `window.confirm` авто-подтверждается → задача hard-удалилась. (2) Слепой поиск кнопки по тексту «Удалить» попадал в swipe-кнопку списка (там удаление БЕЗ confirm, прямое). Итог: снёс реальную задачу id 73, восстанавливал руками (psql INSERT; гочи not-null: source/order_index).
**Применять:** НИКОГДА не автокликать delete/destructive на проде. Деструктивный UI проверять (а) на локальном/preview-инстансе, (б) статичным рендером разметки (как мокап) для визуала, (в) если на проде — `dialogAction:"dismiss"` И целиться ТОЧНО в кнопку, ведущую через confirm (не swipe-direct). deleteTask в planner = HARD delete (session.delete + дети), не архив → не восстановить без бэкапа. Прод-данные владельца священны [[feedback-dont-break-ledger]].

**Симптом:** в PWA удаление задачи/проекта «висело» — нажал Удалить, ничего. В Telegram работало.
**Корень:** index.html грузит `telegram-web-app.js` всегда → `window.Telegram.WebApp` существует и в PWA (вне Telegram). `tg()?.showConfirm` — метод ЕСТЬ (truthy), но вне Telegram-клиента он не показывает диалог и **не вызывает колбэк** → промис никогда не резолвится → действие висит. Фолбэк `window.confirm` стоял в ветке `else` (метод-то есть) → не достигался.

**Применять:** любую Telegram-only фичу (showConfirm/showPopup/HapticFeedback/MainButton…) гейтить по `isTelegram()`/`initData`, НЕ по `tg()?.method`. tg() в PWA = заглушка-объект, методы есть, но no-op/не-зовут-колбэк. Связано: [[planner-pwa-install]].

## Смарт-списки «Сегодня» брали дату СЕРВЕРА (UTC), не устройства → расхождение (2026-06-21)
**Симптом:** «Сегодня» не показывал задачи на сегодня. Бэк отдавал 12 (count совпадал со списком), но это были задачи 21 июня, а у пользователя на устройстве/таймлайне — 22 июня.
**Корень:** бэк `list_tasks scope=today/overdue/week` и `smart_list_counts` брали `date.today()` СЕРВЕРА (Hetzner=UTC). Сервер UTC=21 июня, устройство (Прага, +2 / или клок-скью) = 22 июня → «сегодня» расходится; задачи 22-го уходили в «Завтра». Таймлайн при этом использовал client `localToday()` → ещё и несогласованность внутри приложения.
**Фикс:** клиент — единый источник «сегодня». Фронт шлёт `today=<дата устройства>` (lib/clientDate.clientToday) в `/tasks` и `/counts`; бэк принимает `ref_date` и анкерит scope today/overdue/week/planned + counts на неё (fallback `date.today()`, обратная совместимость). +тест ref_date.
**Применять:** в приложении с пользователем в одной TZ и сервером в другой (UTC) «сегодня/просрочка» считать по дате КЛИЕНТА, не сервера. Один источник дня на фронте (clientToday), прокидывать в API. Грепать `date.today()`/`new Date()` в дате-логике на предмет server-vs-client.

## PWA standalone: body{position:fixed} scroll-lock ломает fixed-оверлеи + SW кэш переживает переустановку (2026-06-21)
**Симптом (только PWA-standalone на iPhone):** шторка обрывалась снизу, под ней чёрный провал, навбар фона уезжал вверх. Десктоп НЕ репродил (chrome: шторка height 852=вьюпорт, полная).
**Корень:** scroll-lock фона делал `body{position:fixed; top:-Y}`. На iOS standalone fixed-оверлеи (`.drawer`/`.drawer-backdrop`) начинают позиционироваться от СДВИНУТОГО body-бокса, не от вьюпорта → провал снизу ≈scrollY, фон полз вверх. **Высотой НЕ лечится** (100dvh/bottom:0 на оверлее не помогли — ICB сам сдвинут). В Telegram/Safari (не standalone) баг не проявлялся.
**Фикс:** position:fixed-lock оставить ТОЛЬКО оверлеям с autofocus-инпутом (composer/деталь — там он против «экран улетает» при фокусе); шторке (без инпута) — лёгкий `body{overflow:hidden}` БЕЗ сдвига. Тогда fixed-оверлеи снова от вьюпорта. Проверка на десктопе: при открытой шторке `body` должен быть `position:static`, не fixed.
**ВТОРАЯ грабля (доставка фикса):** service-worker PWA на iOS отдаёт СТАРЫЙ кэш даже после удаления иконки с экрана и reload — иконка≠очистка. Чистит надёжно только: Настройки→Safari→Дополнения→Данные сайтов→удалить домен (или в DevTools unregister SW + caches.delete). Тестировать прод-PWA-правки = сначала сбросить SW, иначе меряешь старый бандл. → [[planner-pwa-install]].
**Применять:** для full-screen фикс-оверлеев на iOS PWA НЕ использовать body{position:fixed} как scroll-lock (если можно overflow:hidden). При «фикс задеплоен, а на устройстве по-старому» — первым подозревать SW-кэш, не код.

## Кастомный transform-скролл таймлайна не скроллил по карточкам (2026-06-21)
**Симптом:** в сформированном дне (Today) скролл драгом ловится только на пустых полях, по карточкам — нет. Apple-календарь скроллит откуда угодно.
**Корень:** Today GPU-transform-скролл (`DayTimeline.tsx`, useEffect ~298) — touch-листенеры на `.cal-grid`. `onTS` бейлил на `.cal-block` (`if (closest(".cal-block,...")) {dragging=false; return}`) → скролл стартовал ТОЛЬКО с пустой сетки. Карточка имеет свои pointer-хендлеры (long-press 220мс «поднять блок»), потому скролл на ней вырубили целиком — но дискриминатор уже был (подъём отменяется при сдвиге >CANCEL_PX).
**Фикс:** (1) убрать `.cal-block` из bail `onTS` → скролл стартует и по карточке; `e.preventDefault()` звать ТОЛЬКО на пустой сетке (`if (!closest(".cal-block")) e.preventDefault()`). **На карточке pd НЕЛЬЗЯ — на iOS убивает синтетический click → ломает tap-open детали.** Нативный скролл на теле и так off (`touch-action:none` на `.cal-block-main`), потому transform-скролл через всплывающие touch-события работает. (2) `onTM` гард `dragRef.current` (активный подъём/ресайз блока → не скроллим заодно).
**Применять:** при кастомном transform/JS-скролле НЕ глуши его на интерактивных детях целиком — пусть дискриминатор жеста (порог сдвига) разведёт скролл vs действие. `preventDefault` на touchstart над кликабельным элементом на iOS убивает последующий click. touch-action:none блокирует нативные жесты, но НЕ диспетчеризацию/всплытие touch-событий. CDP-touch iOS-скролл не репродит → финал на устройстве. Связано: [[feedback-visual-verify]].

## Цвет за скруглённый угол карточки = overflow:hidden НЕ клипает на дробном transform-слое → clip-path (2026-06-20)
**Симптом:** у тинт/бордюр-карточек (блоки таймлайна `.cal-block`, all-day `.cal-chip`, строки списка `.task-row`/`.task-swipe`) цвет вылезал тонкой ДУГОЙ за правый/левый скруглённый угол на iOS. В списке — красный (слот свайпа «Удалить» за строкой), на таймлайне — тинт/border-left.
**3 ЛОЖНЫХ ФИКСА (вслепую, НЕ повторять):** (1) child сам скругляет фон + radius:0/var; (2) `translateZ(0)` на родителе `.task-swipe`; (3) `translateZ(0)` на самом элементе («промотировать в свой слой»). Все мимо — translateZ сам шов и ПРОВОЦИРУЕТ. `-webkit-mask-image: radial-gradient` тоже НЕ помог.
**КАК ВОСПРОИЗВЁЛ (ключевой приём!):** десктоп-Chromium ОБЫЧНО не показывает (целочисленный сдвиг). Репро: поставить родителю `transform: translate3d(0,-0.37px,0)` (ДРОБНЫЙ — имитирует инерцию скролла `.cal-grid`) + элементу `transform: scale(7)` + зум угла. Тогда `overflow:hidden+border-radius` светит цвет сзади тонкой дугой — видно в Chromium через chrome-devtools (preview-app-mock на vite). Запуск Chrome для MCP: `Google Chrome --remote-debugging-port=9222 --headless=new`, потом navigate.
**ИСТИННЫЙ КОРЕНЬ:** `overflow:hidden` + `border-radius` НЕ обрезает скруглённый угол идеально, когда контейнер на дробно-сдвинутом GPU-слое (composited + non-integer offset). WebKit рисует контент/задний слой на ~1px за радиус.
**ФИКС (подтверждён в репро живьём):** `clip-path: inset(0 round R)` — клипает точно, GPU-аккуратно, угол чистый. Добавлен к `.task-swipe`/`.cal-block`/`.cal-chip` (оставил overflow+radius как fallback). Клипает и задний слой (свайп), и border-left, и тинт.
**Применять:** скруглённая карточка с цветом/задним слоем внутри transform-контекста (GPU-скролл/инерция) на iOS → клип через `clip-path: inset(0 round R)`, НЕ только `overflow:hidden`. Десктоп-репро = дробный `translate3d` на предке + scale-зум. translateZ-промоция НЕ лечит. Связано: [[feedback-visual-verify]].

## iOS-таймлайн: long-press-создание vs нативный скролл vs лупа = трилемма → GPU-transform скролл (2026-06-20)
**Симптом:** long-press-создание задачи на таймлайне Today «не работает ниже now-линии». Долгая сага диагностики.
**ЛОЖНЫЕ СЛЕДЫ (каждый отвергнут замером, НЕ повторять):** now-line (`pointer-events:none` ✓ не виновата) · FAB/таб-бар клиренс (перекрывают лишь низ ~56-130px) · код-гейт по `nowMin` (нет, grep) · «граница=now» = артефакт авто-скролла (тестируемая зона = ниже now) · `user-select:none`+`touch-callout:none` (применяются — computed `none` — но Telegram-WebView лупу НЕ глушат) · `selectstart`/`dragstart` preventDefault (не глушат лупу) · `disableVerticalSwipes` (уже был).
**ИСТИННЫЙ КОРЕНЬ (трилемма iOS WebView):** на ОДНОЙ скролл-поверхности нельзя одновременно: (а) нативный плавный скролл, (б) надёжный long-press, (в) без лупы выделения. iOS либо крадёт удержание под скролл (`pointercancel`=PCANCEL до взвода), либо на hold показывает лупу text/image-выделения. Лупу + перехват глушит ТОЛЬКО `preventDefault` нативного `touchstart` — но он убивает и нативный скролл.
**РЕШЕНИЕ (что в итоге сработало):** **GPU-transform скролл**. `.cal-scroll`(static) = клип-вьюпорт `overflow:hidden` фикс-высоты (ставится из JS = `visualViewport.height - rect.top - 76`); контент `.cal-grid` двигается `transform: translate3d(0,-offset,0)` НА КОМПОЗИТОРЕ (плавно как нативно). Нативный скролл выключен (`touchstart` preventDefault на пустой сетке → лупы нет, iOS не крадёт → long-press надёжен). Драг/инерция — вручную (touch-события → offset, EMA-скорость, momentum `v*=0.95`). Создание (pointer-жест) работает поверх: `gridTop()` через `getBoundingClientRect` учитывает transform → расчёт минут верен (`pointerToMinutes` с scrollTop=0). Прыжок к now = `setOff(nowTopPx - 70)` через `scrollToNowKey`-проп от Today. На блоках/инпуте `touchstart` НЕ глушим (`closest('.cal-block,.cal-draft,input,...')`).
**ПРОМЕЖУТОЧНЫЕ (НЕ хватило):** ручной `scrollTop` (главный поток → лагало); `selectstart`-guard (лупа осталась); CLAIM-после-удержания (PCANCEL до 110мс).
**КЛЮЧ ПЛАВНОСТИ (не очевидно!):** transform сам по себе НЕ убрал лаг — джанк был в **чтении `scrollHeight/clientHeight` на КАЖДЫЙ touchmove** (форсит reflow/layout) + rAF-батч (кадр задержки). Фикс: кешировать `maxOff` (recalc раз на touchstart/resize, НЕ в move) + применять `transform` ПРЯМО в touchmove (без rAF — GPU-transform дешёвый, reflow не нужен). После этого — плавно. Урок: в touch-хот-пути НИКАКИХ layout-reads (offsetHeight/scrollHeight/getBoundingClientRect) — кешируй; и не батчь дешёвые GPU-записи через rAF (добавляет лаг).
**Применять:** Telegram iOS WebView + кастомный long-press на скролле = делай клип-вьюпорт + `translate3d` на композиторе, не борись с нативным скроллом. Десктоп-мышь НЕ репродит touch-перехват/лупу — слать сборку на устройство владельцу (быстрый цикл rsync→build→up). На каждой неудаче — добавлять on-screen дебаг (копит последние строки), владелец читает трейс `DOWN/CLAIM/ARMED/PCANCEL`. Связано: [[planner-now-line-pointer-bug]], [[feedback-visual-verify]].

## Десктоп-preview ≠ iOS: клава/visualViewport/focus (2026-06-20)
**Грабли:** в Telegram (iOS) лист создания проекта улетал вверх при клавиатуре + тап по иконке не открывал эмодзи-клаву. Мой preview в десктоп-хроме показывал «всё ок» — он НЕ воспроизводит iOS-клавиатуру, visualViewport-сжатие, нативный focus.
**Корни+фиксы:**
- Лист `inset:0`+`max-height:85dvh` → при клаве (~40% экрана) верх за экраном. Фикс: Sheet привязан к `visualViewport` (top+height), max-height=vp.height.
- Программный `input.focus()` на `opacity:0`-инпуте iOS игнорит → клава не открывалась. Фикс: реальный input ПОВЕРХ иконки (opacity:0, pointer-events:auto) — прямой ТАП = нативный фокус = клава.
**Применять:** iOS-специфику (клавиатура, focus, safe-area, 100vh vs dvh, position:fixed+keyboard) НЕ верить десктоп-preview — писать защищённо by-construction (visualViewport-sizing, реальный input-оверлей вместо программного focus) И подтверждать у владельца на устройстве. ## position:fixed внутри transformed-предка ломается → портал (2026-06-20)
**Грабли:** ⋯-меню/лист проекта (через Sheet) «висели в воздухе» — рендерились внутри `.drawer`, у которой `transform`(slide-анимация)+`will-change:transform`. Любой `position:fixed`-потомок такого предка позиционируется относительно ПРЕДКА, не вьюпорта.
**Фикс:** `Sheet` → `createPortal(.., document.body)` — выходит из transformed-поддерева, fixed резолвится к вьюпорту.
**Применять:** оверлеи/шиты/модалки всегда порталить в body, особенно если предок имеет transform/filter/will-change/contain.

## Telegram WebView глушит window.confirm/alert (2026-06-09)
Нативные `window.confirm`/`alert`/`prompt` в Telegram Mini App WebView НЕ работают (no-op, confirm→false). Симптом был: «Удалить» → подтверждение есть, но ничего не происходит. Всегда использовать `tg().showConfirm(msg, cb)` / `showAlert` (Telegram WebApp SDK), с фолбэком на window.* для браузера/харнеса. Хелпер `confirmDelete` в TaskDetail.tsx.

## Жест-создание на скролл-контейнере: long-press-гейт обязателен (2026-06-09)
Если жест создания (тап/драг по сетке) перехватывает pointermove сразу — ломается нативный скролл таймлайна («экран колдоёбит, ничего нельзя»). Решение: создание-протяжка только после long-press (как перенос блоков); обычный драг = скролл; тап = быстрое создание. scroll-lock body:fixed для ИНЛАЙН-элемента (в потоке) НЕ нужен — он рвёт экран; нужен только для оверлеев. scrollIntoView нельзя вешать в ref-колбэк (зовётся каждый ререндер → прыжки на каждый символ).

## Гейт пропускает CSS-коллизии классов — нужен визуал-диф (2026-06-20)
**Грабли:** легенда Ганта (T3) на проде рисовала серые круги поверх свотчей. Корень: класс `sw` в Gantt.tsx совпал с глобальным `.sw` (toggle-свитч), чей `::after` = серый круг-knob (19×19, radius:50%) налезал на каждый свотч. Чинил переименованием `sw`→`gsw` (T3-scoped).

2. **Generic-имена классов = мина.** `sw`/`it`/`tg`/`dot` в новом экране могут совпасть с глобальными. Скоупить под экран (`gsw`, `.t3 .x`) ИЛИ грепать глобал перед использованием.
3. **GOTCHA повторилась:** playwright reuseExistingServer:true + стейл-vite чужого worktree на :5173 → тестит ЧУЖОЕ дерево (22 ложных фейла). Убивать `lsof -ti :5173` чужих worktree перед e2e.
