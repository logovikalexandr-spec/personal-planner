# Спека: Конвейер «Замысел → Продукт» (fidelity pipeline)

> ⛔ **УСТАРЕЛО (2026-06-14, профи-аудит).** Заменено: [конвейер v2 — Playwright](2026-06-14-конвейер-v2-playwright-design.md). Этот файл = история решения. Анти-паттерны v1: пиксель-диф мокап↔рендер, chrome-devtools MCP как гейт, инертный YAML-контракт, getComputedStyle как главная защита.

> Дата: 2026-06-14. Проект: personal-planner / planner-v2.
> Цель владельца: «дал задание — получил то, что хотел». Утверждённый мокап со всеми фичами переезжает в деплой как полноценный продукт **без потерь**.
> Проблема: «испорченный телефон» — на каждой границе перевода (идея→мокап→код→рендер→поведение→деплой) часть замысла протекает. Сегодня контролёров мало, и они проверяют «таск выполнен», а не «это то, что хотел».
> Решение: (1) превратить утверждённый мокап в **явный проверяемый КОНТРАКТ** (линейку); (2) поставить **гейт после каждой границы**, и каждый гейт сверяет с контрактом, а не с «работает вообще».

---

## Центральная идея

```
МОКАП (картинка)  +  КОНТРАКТ (список «что должно быть», текст)  =  ЛИНЕЙКА
```

Контракт делается **один раз**, в момент утверждения мокапа (Гейт 0→1). Дальше каждый гейт прикладывает линейку. Без контракта «что хотел» живёт в голове + картинке и дрейфит; с контрактом — машина держит верность.

**Распределение труда:**
```
ВЛАДЕЛЕЦ → только Гейт 0 (утвердить мокап+контракт) + финальное ОК
МАШИНА   → держит верность на Гейтах 1–6 автоматически
НИЧЕГО не доходит до деплоя непроверенным против контракта
```

---

## Артефакт: КОНТРАКТ экрана

Файл на экран: `контекст/контракты/<screen>.md`. Источник истины «definition of done». Создаётся из утверждённого мокапа.

Формат (пример — T2 Календарь, неделя, drag time-blocking):

```yaml
screen: T2-calendar-week
mockup: база-проекта-v3/pages/T2a-calendar-week.html
approved_at: 2026-06-14

# ЧТО ДОЛЖНО РАБОТАТЬ (поведение, проверяет Гейт 5)
behaviors:
  - id: drag-task
    truth: "задачу можно тянуть по таймлайну"
  - id: snap-15
    truth: "при отпускании прилипает к 15-мин сетке (не к часу)"
  - id: color-project
    truth: "цвет блока = цвет проекта"
  - id: persist
    truth: "после перетаскивания новое время сохраняется (refresh не сбрасывает)"

# КАК ДОЛЖНО ВЫГЛЯДЕТЬ (токены/структура, проверяет Гейт 4)
visual:
  - element: ".time-block"
    tokens: { borderRadius: "8px", fontFamily: "Geist" }
  - element: ".time-block[data-project]"
    rule: "backgroundColor = цвет проекта (тинт), НЕ ember"
  - rule: "акцент ember #EE8A3C только на активном табе/кнопке"
  - rule: "нет emoji в хроме"

# СОСТОЯНИЯ (проверяют Гейт 4 + 5)
states:
  - empty: "нет задач на день → заглушка-скелетон, не пустота"
  - loading: "скелетон, не круглый спиннер"
  - error: "сообщение + ретрай"

# ФЛОУ (проверяет Гейт 5 — сквозной сценарий)
flows:
  - "открыл неделю → перетащил задачу на 14:15 → refresh → задача на 14:15"
```

## Гейты (контролёры) — по одному на границу

| # | Граница | Гейт | Кто (агент) | Сверяет | Статус |
|---|---|---|---|---|---|
| **0** | идея → мокап | РАЗВЕДКА | product-depth + designer | мокап покрыл все фичи/флоу/состояния → владелец утвердил | ✅ есть |
| **1** | мокап → контракт | КОНТРАКТ | `contract-writer` (нов.) | каждую фичу/состояние/токен из мокапа → проверяемый пункт | ❌ дыра |
| **2** | контракт → план | ПЛАН | `plan-checker` (нов./reviewer) | план покрывает КАЖДЫЙ пункт контракта (нет пропусков) | ⚠️ частично |
| **3** | план → код | ТЕСТЫ | backend/frontend (TDD) | поведение зелёное (pytest/vitest) | ✅ есть |
| **4** | код → рендер | ВИЗУАЛ | `visual-verifier` (нов.) | рендер == мокап: токены (getComputedStyle vs DESIGN.md) + структура + состояния | 📝 спека готова |
| **5** | рендер → поведение | GOAL-BACK | `behavior-verifier` (нов.) | каждый behavior/flow контракта РАБОТАЕТ end-to-end (данные текут, не пустышка) | ❌ дыра |
| **6** | билд → деплой | ДЕПЛОЙ-ВЕРНОСТЬ | `deploy-verifier` (нов.) | Гейты 4+5 прогнаны против ПРОДА (не только локального билда) | ❌ дыра |

Каждый гейт: вход = контракт + артефакт; выход = PASS / BLOCK + список несоответствий → назад в стройку → повтор до PASS.

### Гейт 1 — contract-writer (краеугольный)
Читает утверждённый мокап (HTML) + спеку разведки → выписывает контракт (формат выше). Владелец сверяет «всё ли я хотел тут есть» **один раз**. Это и есть «линейка». Без него остальные гейты не с чем сверять.

### Гейт 4 — visual-verifier
Детали в [2026-06-13-визуал-верификатор-design.md](2026-06-13-визуал-верификатор-design.md). Теперь сверяет с разделом `visual:` + `states:` контракта (а не «на глаз с мокапом»). chrome-devtools: рендер preview → скрин → getComputedStyle → сверка токенов.

### Гейт 5 — behavior-verifier (вторая большая дыра)
chrome-devtools **прогоняет живой экран по каждому `flow` контракта**: кликает, тянет, вводит, проверяет результат и persist (refresh). Это goal-backward: не «компонент есть», а «фича работает». Проверяет `behaviors:` + `flows:`. BLOCK при любом несработавшем сценарии.

### Гейт 6 — deploy-verifier
После деплоя гоняет Гейты 4+5 против **прод-URL** (Telegram Mini App). Закрывает «на проде не то, что верифицировали». Заменяет старый «bundle-hash + глаз в Telegram».

### Независимый глаз (опц., Трек 2)
Гейты 4/5 — это Claude, судящий свой код (слепая зона). Митигация на старте: сверка **программная** (числа/сценарии, не «похоже»). Если дрейф останется → скрин/результат → vision-AI (GPT/Gemini) как второй судья. Через chrome-devtools с жёстким хуком-гейтом захода (Трек 2, отдельная спека).

## Поток целиком

```
ЗАМЫСЕЛ
  │ Гейт 0  product-depth+designer → мокап покрыл всё → ТЫ утвердил
МОКАП
  │ Гейт 1  contract-writer → КОНТРАКТ (линейка) → ТЫ сверил «всё ли хотел»
КОНТРАКТ ◄═══════ источник истины, на него смотрят все гейты ниже
  │ Гейт 2  plan-checker → план покрывает каждый пункт контракта
ПЛАН
  │ build TDD (backend ∥ frontend)
КОД
  │ Гейт 3  тесты зелёные
  │ Гейт 4  visual-verifier → рендер == visual+states контракта
  │ Гейт 5  behavior-verifier → behaviors+flows контракта работают end-to-end
ВЕРИФИЦИРОВАННЫЙ БИЛД
  │ Гейт 6  deploy-verifier → Гейты 4+5 против ПРОДА
ПРОДУКТ == ЗАМЫСЕЛ ✅  → ТЫ: финальное ОК
```

## Вшивка в agent-team (TEAM.md)

- Фаза 1 (Разведка): + шаг Гейт 1 → contract-writer пишет контракт, владелец сверяет.
- Фаза 2 (Сборка): план сверяется с контрактом (Гейт 2); build по контракту.
- Фаза 3 (Гейт): порядок = тесты(3) → visual-verifier(4) → behavior-verifier(5) → reviewer (читает их вердикты, MERGE/BLOCK). После деплоя — deploy-verifier(6).
- reviewer НЕ выносит MERGE, пока Гейты 4 и 5 не PASS против контракта.

Новые агенты в `planner-v2/.claude/agents/`: `contract-writer`, `visual-verifier`, `behavior-verifier`, `deploy-verifier`. (plan-checker — либо новый, либо роль reviewer'а.)

## Скоуп и порядок внедрения

Не строить всё сразу. Порядок по «болит / разблокирует»:

1. **Гейт 1 contract-writer** — без линейки остальное не с чем сверять. Фундамент.
2. **Гейт 4 visual-verifier** — спека готова, закрывает визуал-дрейф (главная жалоба).
3. **Гейт 5 behavior-verifier** — закрывает «фича не работает как задумано».
4. **Гейт 6 deploy-verifier** — закрывает «на проде не то».
5. **Гейт 2 plan-checker** — формализовать покрытие плана.
6. **Трек 2 / независимый глаз** — если самопроверки не хватит.

Каждый гейт = отдельная фаза сборки (своя спека → план → исполнение).
