## Сделано
Один форк правит модель + одну миграцию, чтобы Гант/Цели/DETAIL-этап/INBOX строились поверх без гонки.

**Модель** (`planner-v2/src/planner/db/models.py`):
- `Stage{id, project_id(FK CASCADE), name, order_index, start_date, end_date, status(done|current|future|late, default future), progress, is_milestone, milestone_date, created_at}`
- `StageDependency{from_stage_id, to_stage_id}` (PK-пара, FK CASCADE). Семантика ребра: `to` зависит от `from` (from = предшественник, критпуть).
- `Project` +`success_probability(int|null)`, `target_date(date|null)`, `ai_notes(JSON|null — список {date,type(accelerate|risk|info),text})`.
- `Task` +`stage_id(FK stage, ondelete SET NULL, null)`.
- `weeks_left` — НЕ колонка, computed в `_to_out` из `target_date`.

**Schemas** (`api/schemas.py`): `StageCreate/StagePatch/StageOut` (с `depends_on_ids`), `ProjectAiUpdate`, `AiNote`. `ProjectOut` +AI-поля +`weeks_left` (аддитивно, старое не сломано).

**Service** `services/stages.py`: CRUD стейджей, авто `order_index`, валидация status/probability(0..100), `_set_dependencies` (дедуп, без самозависимости), `update_project_ai`. `delete_stage` — **портируемая зачистка** (явный UPDATE task.stage_id=NULL + DELETE deps; SQLite в тестах не форсит FK ondelete).

**Routes**: `api/routes/stages.py` (GET list `?project_id=` / POST / PUT / DELETE, под `require_owner`), `PUT /api/projects/{id}/ai` (ai_notes сериализуется `mode="json"` — иначе date в JSON-колонке падает). Роутер зарегистрирован в `app.py`.

**Migration** `e5f6a7b8c9d0_fork0_stages_project_ai.py` (head: d4e5f6a7b8c9 → e5f6a7b8c9d0).
