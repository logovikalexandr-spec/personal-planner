## Рецепт: довести экран X до мокапа + залочить

1. **Открой мокап вживую** (память [[feedback-open-mockups-local]]): `open база-проекта-v3/pages/<X>.html`. Достань ecode-легенду из `контекст/реестр-мокапов.md`. Флоу/состояния — `<X>-flows.html` / `<X>-состояния.html`.
2. **Собери preview** `src/preview-<x>-mock.tsx` + `preview-<x>-mock.html` (копируй паттерн preview-t1-full: импорт `theme.css`, мок `window.fetch` по эндпоинтам из `src/api.ts`, рендер реального компонента/экрана). Для persist — stateful-мок в `localStorage` (см. preview-t1-full `?persist=1`).
3. **Сверь глазами** preview vs мокап (chrome-devtools или `open`). Найди дрейфы. Чини КОД под мокап (не наоборот — мокап=истина, слово владельца).
4. **data-testid** на интерактив (бургер/кнопки/блоки) — как в Today.tsx (`btn-date`, `task-N`, …).
5. **Спека** `tests-e2e/<X>.spec.ts`: заголовок теста = критерий приёмки. Покрой ecodes + флоу + состояния + `toHaveCSS` токен-смоук + `toHaveScreenshot` визуал-baseline (chromium, часы морозь `page.clock` если есть now-line/дата). В конце — `// COVERAGE-DEFER` явным списком (что не покрыто и почему).
6. **coverage** `bash tests-e2e/coverage.sh ../../база-проекта-v3/pages/<X>.html tests-e2e/<X>.spec.ts` → PASS (0 дыр).
7. **Гейты зелёные:** `npm run lint:tokens && npm run test && npm run e2e`.
8. **Baseline утверждает ЧЕЛОВЕК** (визуально), потом запускает САМ: `npx playwright test <X> --update-snapshots --project=chromium`. **АГЕНТ baseline НЕ обновляет** (анти snapshot-fatigue; config `updateSnapshots:"none"`).
9. **Деплой** (см. ниже) → проверить на проде.

## Деплой (прод обновляется так)

```bash
# 1. синхронизировать фронт-исходники
cd planner-v2 && rsync -az \
  --exclude node_modules --exclude dist --exclude test-results \
  --exclude playwright-report --exclude .env --exclude 'tests-e2e/__snapshots__' \
  -e "ssh -o BatchMode=yes" \
  frontend/ root@188.245.42.4:/root/planner-v2-src/planner-v2/frontend/
# 2. пересобрать образ + поднять (на сервере)
ssh root@188.245.42.4 'cd /root/planner-v2-src/planner-v2 && \
  docker compose -f docker-compose.prod.yml build && \
  docker compose -f docker-compose.prod.yml up -d'
# 3. проверить СНАРУЖИ (хайрпин с сервера НЕ работает → curl с локалки/браузера)
curl https://planner.188.245.42.4.nip.io/api/health   # → 200
```
- **URL прода = `planner.188.245.42.4.nip.io` (nip.io!), НЕ sslip.io** (у sslip серта нет → TLS-ошибка, ложная «прод упал»).
- Прокси — общий `ledger-caddy` (80/443) на сети `planner-v2_planner_net`. **ledger не трогать.**
- В обычном браузере `/app/` покажет «Не удалось загрузить» (пустой initData → 401) — это НЕ баг; в реальном Telegram данные есть.
- Бэкенд-миграции — только если менял модели (`alembic`); фронт-only деплой миграций не требует.

## Железные правила (из этой сессии)
- **Мокап = контракт-истина** (слово владельца). Код уехал — чинить код, не мокап.
- **Baseline сверяет код с самим собой** (регрессия), НЕ с мокапом. «Совпало с мокапом» — пока человек/глаза (или будущий vision-судья, Track-2). Поэтому шаг 3 (сверка глазами) обязателен.
- **Гейт не запускается сам** (нет pre-commit/CI) — это TODO #1. Пока гонять руками перед коммитом/деплоем.
- **Бэклог дрейфа** велик (аудит): половина экранов не построена/уехала. Гейт = защита будущего, не аудитор прошлого.
