# Волна 1 — Workout-лог (подраздел Цели) · спека после grill

> Результат grill-me 2026-06-21. Фича = подраздел «Тренировки» ВНУТРИ Цели «Recomp 90д».
> Связано: [[программа]], [[роль]], [[память]].

## Решения (зафиксировано)

| # | Ветка | Решение |
|---|---|---|
| Q1 | Ввод | **Гибрид** — шаблоны сессий как основа + правка упражнений на лету |
| Q2 | Каталог | **Предзаполнен** упражнениями из [[программа]] + «добавить своё» (стабильный exercise_id) |
| Q3 | Данные подхода | вес × повторы (**RPE — опц.поле**), флаг разминки, **заметка-упражнение**, **ревью-сессии** (свободный текст) |
| Q4 | Мозг | **Авто-LLM-разбор после каждой трени** + детерминированная подсказка веса в коде (мгновенно/даром) |
| Q5 | Канал | **Telegram-пуш** сразу после трени + разбор пишется в Цель (ai_notes) как история |
| Q6 | Объём | **Полная фича за заход**: петля + история упражнения + PR + график + привязка к мезоциклу |
| Q7 | Полномочия | **Тренер сам правит след. сессию** (веса/подходы/упражнения), у каждого изменения «почему» + откат в 1 тап |

## Жёсткие рейлы (неприкосновенно)
- **Health-ограничения тренер НЕ может нарушить** even авто: нет флексии пресса (скручивания/подъём ног в висе), нет велик-кардио в острые фазы таза, кор только анти-экстензия, без экстрим-Вальсальвы. Список — из [[программа]] §0.
- Каждое авто-изменение программы — с пометкой причины + reversible.
- Red flags здоровья (боль таз/спина) → стоп, к [[health]], не «продавливать».

## Модель данных (новые сущности planner)

- **Exercise** (каталог): id, name, muscle_group, equipment, is_custom, default_rep_low, default_rep_high, notes. Сид из программы.
- **WorkoutTemplate**: id, project_id(→Цель), name (Верх-Сила/Низ-Квад/Верх-Гиперт/Низ-Задняя), order_index.
- **TemplateExercise**: id, template_id, exercise_id, order_index, target_sets, rep_low, rep_high.
- **WorkoutSession**: id, project_id, template_id(nullable, гибрид), stage_id(авто по дате=мезоцикл), date, review_note, duration, created_at.
- **SetLog**: id, session_id, exercise_id, set_index, weight, reps, rpe(nullable), is_warmup, note, done.
- (PR/1ПМ — расчётно из SetLog: Epley est-1RM + rep-PR, не отдельная таблица; кэш опц.)

## Поведение

- Старт сессии из шаблона → авто-подставляет упражнения + **прошлые веса + целевой вес/повторы** (детерминир. прогрессия).
- Лог подхода: вес/повт (+опц RPE), флаг разминки, заметка.
- Конец: ревью-сессии (свободный текст) → Сохранить.
- После сохранения: бэк зовёт LLM-тренера → разбор (читает сессию+историю+ревью+[[программа]]+[[память]]) → правит след. сессию (с «почему») → пуш в TG + запись ai_notes в Цель → апдейт success% + статус этапа.
- История упражнения: график веса/тоннажа/est-1ПМ + PR-метки.

## Детерминированная прогрессия (в коде, без LLM)
- Добил верх диапазона во ВСЕХ рабочих подходах (RPE≤8 если задан) → предложить +вес (изоляция +1.25–2.5, база +2.5–5).
- Повторы упали 2 трени подряд → флаг тренеру (LLM решает: разгрузка/замена).

## Процесс сборки (правила planner)
1. **Мокап-first:** живой компонент-preview подраздела (3 экрана: список сессий+история / активная сессия / история упражнения) с мок-данными → согласование Александра.
2. Бэк: сущности + Alembic-миграция + сид каталога/шаблонов + API + LLM-интеграция (ключ, промпт тренера из [[роль]], async-джоб после save).
3. Фронт: проводка на реальный бэк.
4. Тесты (pytest + vitest) + деплой + **визуал-проверка** (fidelity-conveyor, не bundle-hash).

## Открыто (решить при сборке)
- Точный UX активной сессии (таймер отдыха, ввод над клавой) — на этапе мокапа.
- Стоимость/модель LLM для разбора (дешёвая модель на рутинный разбор?) — при бэк-интеграции.
