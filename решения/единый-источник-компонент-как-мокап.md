# Решение: единый источник — компонент = мокап (2026-06-20)

> Статус: ПРИНЯТО владельцем. Отменяет двойную реализацию экранов.
> Корень боли «прописали фичу + мокап → собрали → хуета». Связано: [[state-matrix]], [[agent-team-волны]], [[learnings]].

## Проблема (корень, не симптом)

Каждый экран реализовывался ДВАЖДЫ:
1. **Мокап** — рукописный HTML/CSS в `база-проекта-v3/pages/*.html`.
2. **Приложение** — React + `theme.css`.

Две разные кодовые базы, разные инструменты, разные имена классов (баг легенды Ганта: класс `sw` в app совпал с глобальным toggle `.sw`). «Утверждённый мокап» НИЧЕГО не гарантировал про app — app собирался заново. Двойная реализация = гарантированный дрейф + двойные баги.

Прежний «конвейер верности» (Playwright baseline) сверял **код сам с собой** (регрессия), НЕ код с мокапом. Сверку «совпало с мокапом» делал человек глазами в Telegram → каждый дрейф падал на владельца. Детализация спеки это НЕ лечит (мокап-легенда был правильный, сломалась реализация).

## Решение

**То, что владелец утверждает, ДОЛЖНО БЫТЬ тем, что едет в прод.** Не HTML-двойник — живой React-компонент.

### Новый процесс на экран
1. **Спека поведения** (product-depth): флоу + матрица состояний (пусто/загрузка/ошибка/edge) + reuse-карта. Без вёрстки-двойника.
2. **Сборка компонента-первой** (frontend): настоящий React-компонент + **fixtures мок-данных** для каждого состояния. Рендерится в `preview-<screen>-mock.tsx` (stateful, `?state=`).
3. **Утверждение ЖИВОГО компонента** в браузере (`open` preview). Владелец смотрит реальный компонент, не картинку. Что одобрил — то и едет.
4. **Проводка на реальные данные** (тот же компонент + API). Подключаем `api.ts`, не меняя вид.
5. **Проверка против РЕАЛЬНОГО бэка** (локальный стек с PG или прод-API), не моканой сети.
6. **Гейт** lint:tokens + vitest + e2e + coverage → деплой.

### Что меняется
- **HTML-мокапы `база-проекта-v3/` = ЗАМОРОЖЕНЫ как дизайн-референс** (намерение/вкус), НЕ переписываются в React. Для НОВЫХ экранов HTML-двойник не создаём вообще.
- **Артефакт утверждения = preview React-компонента**, не `.html`.
- Playwright baseline теперь осмыслен: эталон = сам компонент (утв. человеком 1 раз) → регрессия ловится, а дрейфа мокап↔код больше нет (один код).
- E2E против реального бэка добавляется к моканому (проводка проверяется до прода).

### Почему так (выгода)
- Корень дрейфа вырезан: один код, нечему расходиться.
- **Меньше работы владельца** — не держим HTML-двойники, не ловим дрейф руками.
- Generic-классы-мины (`sw`/`it`/`dot`) ловятся сразу при рендере живого компонента.

## Долг перехода (foundation)
Текущие 5 табов собраны СТАРЫМ путём (из HTML) → несут накопленный дрейф (легенда Ганта — первый найденный). Нужен разовый **исчерпывающий свип**: каждый экран × каждое состояние × каждый флоу → рендер живого компонента → сверка с мокапом-референсом → починка → проверка проводки на реальном бэке. После этого все экраны = чистый эталон, дальше живём по новому процессу.
