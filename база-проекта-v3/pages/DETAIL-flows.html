DETAIL «Этап проекта» — функциональные флоу

Блок этапа в детали задачи: каждое касание. Зелёное = рекомендация/успех, красное = деструктив. Модель: Task.stage_id → Stage{order_index, name, status: done|current|future|late, progress}. Цвет метки: current=ember · late=danger «!» · future=steel · done=zima. Это контракт Фазы 2.

current — текущий этап late — просрочен «!» future — впереди done — завершён

1 · Задача С этапом → блок в детали (где стоит)

Где: поле «Этап проекта» в детали, сразу под атрибутами, над чеклистом. Что: кольцо n/m + «Этап N · имя» + «Проект · до DD» + chevron «сменить ›».
контекст: место блока в детали

2/3
Чеклист · 2 из 3
Блок = поле, не метка. Тапается весь ряд (или chevron) → шит выбора. Кольцо показывает позицию этапа в проекте (3 из 5), цвет current=ember. Стоит над чеклистом — этап задаёт «куда эта задача в цели», чеклист — «как её сделать».

current — кольцо/число ember (по умолчанию активный этап). late — danger + значок «!» в имени + красная подпись «просрочен N дней». future — кольцо пустое (steel), число steel, подпись «с DD». Один акцент-правило соблюдено: ember только для current, остальное — служебные danger/steel.

Когда у задачи нет этапа, поле не исчезает — оно зовёт привязать. Та же кнопка открывает тот же шит выбора, что и chevron «сменить». Если у задачи вообще нет проекта — поле «Этап» скрыто целиком (этап существует только внутри проекта).

Список = все этапы проекта по порядку. done — зелёный номер, future — серый, текущий выбор — ember-фон + галка. Поздний этап (late) пометился бы danger-номером. Тап по любой строке = выбрать. Внизу — «Убрать этап» (если этап уже стоял). Создавать этап тут нельзя — этапы живут в проекте/Ганте (T3b/T4d).

Где: «Убрать этап» внизу шита. Что: подтверждение → блок становится плейсхолдером «+ добавить».

task.stage_id = null. Лёгкое подтверждение, не «навсегда» — данные задачи целы, теряется лишь связь с этапом (обратимо привязкой). Текст честно поясняет последствие для прогресса. После — поле возвращается в состояние «без этапа» (флоу 3).

7 · Edge: у проекта НЕТ этапов → шит пустой

Когда: проект есть, но Stage[] пуст. Что: шит показывает пусто-состояние «сначала создай этап».
шит без этапов
Этап проекта
Продать ZIMA · этапов пока нет
В проекте ещё нет этапов
Этапы создаются в самом проекте — в «Цели» или на Ганте. Привязать задачу можно после.
Открыть проект «Продать ZIMA»
Не тупик: шит честно говорит, что этапы живут в проекте (T4d-detail / T3b-gantt), и даёт кнопку перейти туда. Привязка к этапу из задачи — только когда этапы уже есть. Соответствует ZERO-AFK: ничего не генерится, только навигация.

8 · Блок «Вклад в успех» — два состояния (оценено / нет)

Где: поле «Вклад в успех» в детали, сразу под «Этап проекта». Что: токен моно NN% + строка-обоснование. Модель: Task.impact: int 0–100 | null. В детали показываем ВСЕГДА (порог 30 действует только в списках). ZERO-AFK: число пишет интерактивный Claude в чате через write-API — не кнопка live-AI.
оценено: impact = 80
Вклад в успехоценил ИИ
80%
Ключевой шаг к продаже студии
Двигает этап «Переговоры»: без согласованной вилки цены сделка не идёт.
не оценено: impact = null
Вклад в успех
—
Ещё не оценено
Обсуди с ассистентом в чате — он проставит вклад.
Оценено — токен ember 80% (число + % справа, без стрелки) + короткое обоснование от Claude, опирающееся на этап/цель. Не оценено (impact==null) — серый «—» + «ещё не оценено · обсуди с ассистентом». Не кнопка генерации: это подсказка-направление, само приложение LLM не зовёт (ZERO-AFK). Цвет токена — служебный (bone/steel на slate), не лезет в цвет-систему строки (кант/фон/этап). В детали порог НЕ действует — даже вклад 12% виден тут, чтобы число объяснялось.
